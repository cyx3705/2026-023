# HistoryVulcan 技术合同

适用源码：**6.1.1**；冻结线：**v6.0.0**。本文件唯一定义 REQ，验收行引用本仓测试方法。

6.1.1 补齐宿主自己的指令自描述（DEC-073）：Diana `diana.docs.audit` 全量体检后全体系只剩宿主 4 处，本版清零并加回归测试。公开 API 不变。

6.1.0 退役消费文档（DEC-072）：发布管线不再复制任何文档，指令说明书只来自注册自描述。公开 API 与 6.0.0 逐字相同，模块不必跟版。

6.0.0 是统一模块契约的收口（DEC-071，设计见 `b-Office/history/6.0.0-统一模块契约设计稿.md`）：宿主给模块的只有一条总线和一个上下文，
契约面有白名单，宿主内部类型全部收回。这是主版本：5.x 编译的模块包不能在 6.0.0 上装载，须重新编译。
5.9.0 是第一段（DEC-070）：只增不删。

## REQ-HOST-090 宿主指令的示例照抄能跑（6.1.1）

宿主注册的每条带参数的指令（含隐藏的）都必须有 Example；示例按宿主解析器解析后指令名就是本条，只用已声明的参数，必填参数全部给出（具名或按位置），
位置参数个数不超过声明的位置参数。参数说明要让调用者照着能填：格式、例子或取值来源。`vulcan.app.set` 的 key/value、`vulcan.svc.autostart` 的示例、
`vulcan.worktree.create` 示例缺的 `agent=` 据此补齐。
验收：`HostSelfDescriptionTests.HostCommandsWithParametersCarryRunnableExamples`。

## REQ-HOST-084 契约面只有白名单里的类型（6.0.0，G1 / G5）

`IModuleContext.Bus` 是 `ICommandBus`（`ExecuteAsync`、`InvokeAsync`、`RequestConfirmation`），`RegisterCommands` 给 `ICommandRegistrar`（只有 `Register(descriptor)`），
`Log` 是只写的 `IModuleLog`。Core 的公开类型严格等于模块开发手册「接入契约」的白名单：`CommandBus`、`CommandRegistry`、`IShellLog`、`ShellLogEntry`、

Services、ServiceHost 没有公开类型（宿主自己的入口经 InternalsVisibleTo 访问）。公开 API 以 6.0.0 为新冻结线：Shipped 即白名单，Unshipped 为空。
`InvokeAsync`（安静执行：不回显、不记结果、不发 `vulcan.command.executed`，确认闸口照旧）是在设计稿之外补进窄总线的：界面取数不是操作，走 `ExecuteAsync` 会刷满控制台。

## REQ-HOST-086 模块调用的来源由宿主盖章（6.0.0）

## REQ-HOST-080 总线事件：具名主题的发布与订阅（5.9.0）

总线除了指令还有事件。主题是小写点分段、至少两段的名字；订阅可写完整主题或以 `.*` 结尾的前缀。
每个订阅按发布顺序串行收到事件，不同订阅互不阻塞；处理器抛出的异常只记进日志类别 `bus.event`，不影响后续投递。

## REQ-HOST-071 开发管线打印的 git 路径不做八进制转义（5.6.1）

`ToolProcess.Execute` 对每一条 git 统一补 `-c core.quotepath=false -c i18n.logOutputEncoding=utf-8`，
按可执行文件名判定，其它工具的参数一个字不动。

- 起因：git 默认 `core.quotepath=true`，把路径里的非 ASCII 字节打成三位八进制码。
  本体系项目名与文件名大量是中文，`vulcan.dev.submit` 摆给人看的**脏文件清单**因此整片是数字串；
  那份清单存在的意义就是让人核对「这次带走了哪些文件」，看不懂等于没有。
- 此前只有 `ToolProcess.Git` 自己拼了这两条 `-c`，而清单走的是 `ToolProcess.Capture`，绕过了它。
  补在进程层是为了不再漏下一个调用点——这类「统一设置」只要有两个入口就一定会漏掉其中一个。
- 两条 `-c` 只影响 git **打印**什么，不影响它做了什么。
验收：`ToolProcessGitOutputTests.EveryGitCallSitePrintsChinesePathsAsCharacters`。
验收：`ToolProcessGitOutputTests.NonGitToolsKeepTheirArgumentsUntouched`。
组件分工见[项目概览](项目概览.md)，模块接入见[模块开发手册](模块开发手册.md)，API 纪律见[冻结合同](冻结合同.md)。

### REQ-HOST-005 结果与进度按形状分级

命令结果与进度行的日志级别由宿主总线决定：CommandResult 不含级别，模块无从声明，
因此规则必须按**消息形状**判，不得按域或命令名列白名单——白名单漏掉的正是下一个模块。

成功结果为单行且不超过 200 字时整条写 Info。多行或超过 200 字时，Info 只写一行提要
（多行取第一行并附「另有 N 行」，单行只报字数），正文原样写 Debug，一个字不丢。
进度行用同一把尺子：一句一行的进度留在 Info，整块贴上来的降到 Debug。
失败结果无论多长都整条写 Error，不降级。

界线 200 字取自三天真机日志的分布：成功结果 1211 条不超过 120 字、31 条落在 121～200，
再往上直接跳到 401 字以上，200 正在那道空档里。

本条只改日志级别。CommandResult 的返回值、MCP 与 CLI 回执、落盘内容都不变。

验收：`CommandBusResultGradingTests.FailureIsNeverDowngradedHoweverLongItIs`。
