# HistoryVulcan 技术合同

适用源码：**5.7.0**；冻结线：**v5.4.0**。本文件唯一定义 REQ，验收行引用本仓测试方法。

## REQ-HOST-072 submit / finish 只需要 `worktree=`（5.7.0）

`vulcan.dev.submit` 与 `vulcan.dev.finish` 唯一必填参数是 `worktree=`（目录名或绝对路径）。
模块由工作区所在项目反查发布登记表：绝对路径问 git 公共 .git 所在目录，目录名在工作区根下找唯一匹配。
`name=` 可省略，写了就必须与反查结果一致，不一致时拒绝并说出两个值；反查不到而写了 `name=` 时按旧规则定位。
submit 的 `msg=` 缺省取工作区名 `<短SHA>-<序号>-<agent>-<slug>` 里的 slug；finish 的 `msg=` 接受但忽略并提示
（finish 是快进合并，不产生提交）。旧写法 `name= msg= worktree=` 行为不变。
验收：`DevPipelineUsabilityTests.SubmitAndFinishRequireOnlyTheWorktree`。
验收：`DevPipelineUsabilityTests.WorktreeProjectIsInferredFromNameOrAbsolutePath`。
验收：`DevPipelineUsabilityTests.ExplicitNameMustMatchTheWorktreeProject`。
验收：`DevPipelineUsabilityTests.WorktreeNameSplitsIntoAgentAndSlug`。

## REQ-HOST-073 dev 工作区内的未提交改动不再要求 `allowDirty`（5.7.0）

dev 工作区由 start 从干净的 HEAD 开出，里面的改动全是本轮要提交的，`vulcan.dev.submit` 与其 dryRun
不再要求 `allowDirty=true`（参数保留为无操作）；回执与 Data 仍列出将提交的文件。
主树上的 `vulcan.release.cycle` 保留这道门。
验收：`DevPipelineUsabilityTests.DryRunSubmitNeedsNoAllowDirtyAndReportsCleanly`。

## REQ-HOST-074 热装回执证明模块真的接上了（5.7.0）

`ModulePackageHotReload.InstallAsync` 装包后对同一模块查一次 `vulcan.module.list`：
没接上（`attached=false` 或带附着失败）、版本不是候选版本、或列表里没有它，一律 `Fail`，
文案给出首条原因并指向宿主日志 `[module.discovery]`；成功时回执写明版本与指令数，Data 带
`Version / ExpectedVersion / Attached / CommandCount / AttachFailures`。列表取不到或形状认不出时写「未核对」，
不冒充成功也不冒充失败。finish 合并后的热装未接上时，合并与回收不回滚，但 finish 的结论为失败。
验收：`DevPipelineUsabilityTests.HotReloadFailsWhenTheModuleDidNotAttach`。
验收：`DevPipelineUsabilityTests.HotReloadFailsWhenTheOldVersionIsStillLoaded`。
验收：`DevPipelineUsabilityTests.HotReloadReportsAttachedModuleAndCommandCount`。

## REQ-HOST-071 开发管线打印的 git 路径不做八进制转义（5.6.1）

`ToolProcess.Execute` 对每一条 git 统一补 `-c core.quotepath=false -c i18n.logOutputEncoding=utf-8`，
按可执行文件名判定，其它工具的参数一个字不动。

- 起因：git 默认 `core.quotepath=true`，把路径里的非 ASCII 字节打成三位八进制码。
  本体系项目名与文件名大量是中文，`vulcan.dev.submit` 摆给人看的**脏文件清单**因此整片是数字串；
  那份清单存在的意义就是让人核对「这次带走了哪些文件」，看不懂等于没有。
- 此前只有 `ToolProcess.Git` 自己拼了这两条 `-c`，而清单走的是 `ToolProcess.Capture`，绕过了它。
  补在进程层是为了不再漏下一个调用点——这类「统一设置」只要有两个入口就一定会漏掉其中一个。
- 两条 `-c` 只影响 git **打印**什么，不影响它做了什么。
验收：`ToolProcessGitOutputTests.EveryGitCallSitePrintsChinesePathsAsCharacters`。
验收：`ToolProcessGitOutputTests.NonGitToolsKeepTheirArgumentsUntouched`。
组件分工见[项目概览](项目概览.md)，消费集成见[模块 API](../package/模块API.md)，API 纪律见[冻结合同](冻结合同.md)。

### REQ-HOST-005 结果与进度按形状分级

命令结果与进度行的日志级别由宿主总线决定：CommandResult 不含级别，模块无从声明，
因此规则必须按**消息形状**判，不得按域或命令名列白名单——白名单漏掉的正是下一个模块。

成功结果为单行且不超过 200 字时整条写 Info。多行或超过 200 字时，Info 只写一行提要
（多行取第一行并附「另有 N 行」，单行只报字数），正文原样写 Debug，一个字不丢。
进度行用同一把尺子：一句一行的进度留在 Info，整块贴上来的降到 Debug。
失败结果无论多长都整条写 Error，不降级。

界线 200 字取自三天真机日志的分布：成功结果 1211 条不超过 120 字、31 条落在 121～200，
再往上直接跳到 401 字以上，200 正在那道空档里。

本条只改日志级别。CommandResult 的返回值、MCP 与 CLI 回执、落盘内容都不变。
