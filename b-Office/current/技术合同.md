# HistoryVulcan 技术合同

## 3.11.2 Completion Addendum

Focused-console completion continues after method selection through registered parameter names and values. Committing a parameter name immediately recomputes its allowed/common values; committing a value advances to the next parameter and closes when no candidate remains. A structural parameter hint that changes neither text nor caret closes without recomputation, preventing an infinite popup loop. This is a Shell-only state-machine fix; Core, CommandBus, parser, and command registration contracts remain frozen.

## 3.11.1 Interaction Addendum

`vulcan.app.focusconsole` is registered in both the service and frontend command registries. The service relays the semantic command when the frontend is connected and otherwise starts the frontend with `--focus-console`; startup executes the same semantic command. The frontend shows and activates the shell, focuses console input, and maximizes the console tool window.

Console completion follows domain -> class -> method -> parameter. Tab confirmation of a domain, class, or method immediately recomputes the next candidate layer; candidates support case-insensitive exact, prefix, and contains ranking.
The assistant is active only while the console is the maximized/focused page. In normal docked layout, typing and Tab stay with ordinary WPF console input: no popup, command-catalog switch, selection movement, or selection commit. `vulcan.command.show` returns additive command annotations together with existing parameter metadata so consumers can interpret registrant-owned completion providers. This is Shell-internal routing and must not change the frozen Core/CommandBus contract.

本文件合并当前有效的需求与架构。详细公共 API、命令参数和消费示例以
`../package/` 下的消费合同为准；历史设计和冻结施工记录不再作为现行实现依据。

### REQ-CMD-010 指令分类法：三段业务指令与两段直接方法（3.4.0，DEC-025）

- 目的：让「域|类|方法」模型只有两种合法形态且判定纯结构化，使目录筛选、控制台补全和
  MCP schema 三处共用同一套判定，不再为影子域留特例路径。
- 要求：
  1. 合法形态恰有两种，全小写、无连字符、不留别名：
     - **三段 `<域>.<类>.<方法>`** —— 业务指令的默认形态；
     - **两段 `<域>.<方法>`** —— 该域的**无类直接方法**，为「插一条快捷方法」保留，
       不属于任何类。
  2. 类推导是纯结构式判定，不做语义猜测：
     段数 ≥ 3 取第二段为类；段数 = 2 判为无类（**不再回退首段作为类**）；
     描述符显式声明的 `CommandClass` 永远优先。
  3. `vulcan` 域内置**三段**指令归入十类：`app`、`cli`、`command`、`ui`、`log`、`mcp`、
     `module`、`prompt`、`svc`、`web`。`cli` 仅承载本地 CLI 自发现；其他新增内置三段指令必须并入既有类。
     内置直接方法（两段）不受十类约束，但同一域的直接方法超过 5 条时应重新评估是否建类。
  4. 「无类」是受控的显示类别：目录与命令集的类筛选含「无类」项，
     该标签只用于显示，不参与类推导。
  5. 不存在没有所有者的域。内置指令域恒为 `vulcan`，模块域由 owner 强制（见 REQ-CMD-011）。
  6. **已注册域是绝对名解析的唯一权威源**：`CommandRegistry` 暴露全部已注册命令名首段的集合，
     随模块装载/卸载动态变化。任何组件都不得硬编码域名字面量。
- 影响面：任何仍在注册两段式指令的消费方，其命令按第 2 条从「类.方法」改判为
  「域的直接方法」，归类显示变为「无类」。命令名与调用方式不变，其首段同时成为已注册域
  并参与绝对名解析。OneHistory 体系内已无此类消费方——本条只对体系外的独立仓库适用。
- 验收：`CommandTaxonomyContractTests` 断言运行期注册表内每条指令都是两段或三段、
  域 ∈ {`vulcan`, 模块域}、三段指令的类 ∈ 十类、两段指令判为无类；
  `vulcan.command.domains` 只报 `vulcan` 与已装载模块域。
- 关联组件：`HistoryVulcan.Core/Commands/CommandRegistry`、各 `BuiltinCommands.*`
- 关联验证：`VERIFY-FULL`

### REQ-CMD-012 域聚焦与绝对名脱固（3.4.0，DEC-025）

- 目的：让用户在长时间只操作某一个域时不必反复输入域前缀，同时**不要求任何域**
  为「退出聚焦」提供指令。
- 要求：
  1. 控制台输入可聚焦到某个已注册域。聚焦期间输入解析恰有两条规则：
     - 输入首段命中**已注册域** → 按绝对名解析，不拼前缀；
     - 否则 → 自动补当前聚焦域前缀。
  2. 由第 1 条推出：`mercury.go`、`vulcan.*` 等在任意聚焦状态下都可直接输入。
     **不得**为退出聚焦在各域内新增指令。
  3. 聚焦状态与控制台域筛选下拉双向同步；下拉选「全部」即退出聚焦。
  4. 首段同时是已注册域、又是当前聚焦域下某个类时按绝对名优先，
     并在补全候选中同时给出两种解释，由用户选择。
- 验收：`CommandTaxonomyContractTests` 与控制台用例覆盖上述四条；
  域清单取自注册表而非常量表。
- 关联组件：`HistoryVulcan.Shell/Console/ConsoleView`、`CommandRegistry`
- 关联验证：`VERIFY-FULL`

### REQ-A4 服务进程摆脱 WPF（4.0.0，DEC-049）

- 目的：服务进程从来没有窗口，此前依赖 WPF 只是为了拿一个 `Dispatcher` 当「排到主线程」

- 要求：`HistoryVulcan.ServiceHost` 不得 `UseWPF`，不得引用 `System.Windows`。消息循环由
  `ServiceRunLoop` 承担，装成 `SynchronizationContext` 后供 `CommandBus.UiContext` 与
  `ModuleHost.UiContext` 使用。`TargetFramework` 保留 `net8.0-windows`——自启动注册表等
  Windows API 仍需要它，这与是否 `UseWPF` 是两件事。
- 要求（语义对齐，本条重点）：替换实现必须保住被取代者的三条语义，否则症状是模块里
  罕见难复现的竞态而非构建错误：
  1. **回调彼此串行且不重入**——模块据此假定投递到 `UiContext` 的回调不并发；
  2. **单个回调抛异常不终结循环**——与 WPF 未处理异常被 App 级处理器吞掉后继续泵消息一致，
     否则一个坏模块能拖垮整个服务进程；
  3. **循环线程上的同步投递直接执行**——与 `Dispatcher.Invoke` 一致，避免自锁。
- 要求：`requestStop` 自带「排到循环上再关」的语义。命令处理器跑在线程池上，同步关停会让
  循环在响应写回之前排空退出。
- 说明：不实现 WPF 的优先级队列。原先唯一用到优先级的地方是把延迟启动任务排在
  `ApplicationIdle`，其真实意图是「排在已入队的启动工作之后」，FIFO 队列天然满足。
- 验收：`ServiceRunLoopTests` 七条用例覆盖上述三条语义、退出码传播、关停后投递被丢弃、
  以及 `SynchronizationContext` 落到同一条串行队列；`ServiceHost` 与 `ServiceCommands` 内
  不再出现 `System.Windows`；ServiceHost 输出目录不含 `PresentationFramework` / `WindowsBase`。
  真机冒烟：无 WPF 循环下 `/api/health` 为 `shells=1`，命令与模块中继正常。
- 关联组件：`HistoryVulcan.ServiceHost/ServiceRunLoop.cs`、`ServiceHost.cs`、`ServiceCommands.cs`
- 关联验证：`VERIFY-FULL`

- 目的：前端切出时，不把"恰好注册在前端"的能力当成"属于前端的能力"一起搬走。
- 要求：命令的指令域由实现方决定。搬迁前逐条判定其真实依赖，只有确实需要 UI
  （`RequiresUiThread = true`、访问 `Clipboard` / 窗口 / 对话框）的才随前端走并按
  `ModuleDomainNaming.ToDomain` 改域名；只依赖总线、设置、数据根的一律归服务侧并保留
  `vulcan.*` 域。
- 已判定：`vulcan.command.run` 无 UI 依赖 → 服务侧（`ServiceCommands`），
  命令名与参数不变；`vulcan.command.copyexample` 需 `Clipboard` → 随 Aurora 并改名
  `aurora.command.copyexample`。
- 要求：`vulcan.command.run` 的相对路径基准必须仍是 `%AppData%\HistoryVulcan`
  （即 `ServiceComposition.DataDirectory`），**不得是其下的 `service` 子目录**，
  否则用户已有脚本的相对路径会在升级后集体失效。
- 要求（搬迁的连带约束）：`vulcan.command.run` 必须进 `McpExposurePolicy` 硬排除。
  搬到服务侧后它会自动成为 MCP 可见工具（真机实测确认它一度出现在可见清单里），
  而它按路径读本地脚本并逐行执行任意命令——只要磁盘上存在一个脚本文件，远程就能一次性
  执行其中任意命令，**包括硬排除表里其他条目所排除的那些**。批量执行入口不得成为逐条
  排除的旁路。**此后凡把命令从前端搬到服务侧，都必须复核其 MCP 可见性变化**：
  前端注册的命令 `PolicyVisible` 恒为 false，搬到服务侧即默认可见。
- 验收：`vulcan.command.run` 在服务侧注册且 `Source` 为 `framework:service`；
  前端不再注册该命令；相对路径脚本在升级前后解析到同一位置；
  `CommandTaxonomyContractTests.ScriptBatchExecutionCannotBypassPerCommandExclusions`
  断言其硬排除存在而同类只读查询命令不受影响。
- 关联组件：`HistoryVulcan.ServiceHost/ServiceCommands.cs`、`ServiceComposition.cs`、
  `HistoryVulcan.Core/Mcp/McpExposurePolicy.cs`、`HistoryVulcan.Shell/BuiltinCommands.Basics.cs`
- 关联验证：`VERIFY-FULL`

### REQ-WEB-001 Web 网关是纯本机 IPC（3.13.0，DEC-045）

- 目的：前后端之间需要一条进程间通道，但这条通道不应顺带提供一个无人使用、无人维护的
  对外接入面。
- 要求：`WebGateway` 固定监听 `http://127.0.0.1:<port>`，绑定地址不可配置；唯一接受的会话必须
  同时满足三条——回环、`ClientKind.Shell`、持本次监听的 `AccessToken`——授予 `read/operate/admin`，
  其余一律 401（DEC-046）。不得存在设备鉴权、配对、可配置令牌、CORS 或绑定地址开关；
  不得注册 `vulcan.web.*` 命令。
- 要求：`AccessToken` 由 `Start` 用密码学随机数换发、`Stop` 清空，经 `endpoint.json` 的
  `accessToken` 字段传给前端。它不得落入设置、日志、命令回显或 MCP 投影。
  **前两条（回环、请求头）任何本机进程都能伪造，实现变更时不得把凭据校验降级为可选。**
- 要求：删除后失败鉴权不再节流。这一让步的成立前提就是"只监听回环"。**任何恢复对外监听的
  改动必须同时恢复按源限流**，不得只恢复监听能力。
- 已知缺口：`WebGateway.RequestWebConfirmation` 与 `/api/confirm` 保留，但 `ServiceHost` 侧
  触发条件（源以 `Web:` 开头）已不可达，前端 `ShellServiceClient` 的 `confirmation` 处理器
  因此挂空。留待网关合并时与确认路由一并处理（见 DEC-045 未尽项）。
- 验收：`FreezeBlockerTests.GatewayAcceptsOnlyTheLoopbackShellSession` 断言普通回环 Web 客户端、
  携带设备鉴权头的客户端、伪造 Shell 头但无券的客户端、持错券的客户端均得 401，持本次凭据的
  同机 Shell 得 200；`AccessTokenIsRegeneratedPerListenAndClearedOnStop` 断言每次监听换发、停止清空；
  `WebGatewayLoopbackClientTests.LoopbackShellSustainsRapidSequentialCommands` 断言前端连续调用不被拦。
- 关联组件：`HistoryVulcan.Services/Web`、`HistoryVulcan.ServiceHost`
- 关联验证：`VERIFY-FULL`、`VERIFY-PUBLIC-API`

## 系统架构

### 系统边界

HistoryVulcan 管理通用壳层能力和扩展合同，不拥有消费应用的业务模型。Core 不依赖 WPF；Services
实现通用服务；Shell 是唯一直接封装 AvalonDock 的层；ServiceHost 提供用户会话无窗后台进程。资源浏览/文件
操作不属于 HistoryVulcan，未来由独立模块提供。

### 组成

| 组件 | 路径 | 职责 | 主要输出 |
| --- | --- | --- | --- |
| Core | `b-Code-HistoryVulcan/HistoryVulcan.Core` | 注册器与命令总线契约（命令、日志、MCP、存储） | `OneHistory.HistoryVulcan.Core` |
| Services | `b-Code-HistoryVulcan/HistoryVulcan.Services` | 设置、文件状态、日志、MCP、模块实现 | `OneHistory.HistoryVulcan.Services` |
| Shell | HistoryAurora | WPF 主壳、停靠 UI、控制台、面板与模块管理 | 已迁出本仓 |
| ServiceHost | `b-Code-HistoryVulcan/HistoryVulcan.ServiceHost` | 无窗服务宿主和 `svc.*` 生命周期 | `OneHistory.HistoryVulcan.ServiceHost` |
| App | `b-Code-HistoryVulcan/App` | 单 EXE 前端/后台入口与 GUI 验收宿主 | win-x64 framework-dependent ZIP |
| Tests | `b-Code-Tests/HistoryVulcan.Tests` | 公开合同、安全、布局与冻结回归 | TRX 与进程退出码 |

### 关键流程

1. 消费方固定包版本，创建 `ShellConfig`，只显式启用需要的模块或 MCP 能力。
2. 普通 EXE 启动 WPF 前端；`--service` 启动后台权威宿主，前端通过 loopback 发布 UI 命令目录并接收中继。
3. Shell 组装日志、布局和窗口；模块通过注册合同增加命令与工具页；全局快捷键只向后台命令总线提交命令文本。
4. 模块候选由宿主 `vulcan.dev.submit` / `finish` 写入 `z-Publish/HistoryX-vX.Y.Z/`；宿主自身候选由 `vulcan.release.cycle` 写入平铺 `z-Publish/host/`。CI 不发布。Diana 不发布。

### 不变量与生成物边界

- Core 保持零 WPF 依赖；AvalonDock 只从 Shell 直接引用。
- 所有命令执行进入同一总线；危险命令进入统一确认边界。
- 正式包和 Z 级快照不直接编辑；权威源是源码、`b-Office/package/` 与发布模板。
- HistoryVulcan 只保留 `ModulesView` 这一套模块管理页面；独立 HistoryVulcan 可执行宿主显式启用 `EnableModules` 并成为
  模块生命周期所有者。Janus 只提供停靠位置与消费配置，后续业务能力以模块接入，不复制页面或第二个 `ModuleHost`。
