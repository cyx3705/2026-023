# HistoryVulcan 验证合同

适用源码：**5.5.0**；冻结线：**v5.4.0**。本仓验证不依赖邻接模块源码或运行区用户数据。

## 门禁

| 编号 | 执行与验收 |
| --- | --- |
| VERIFY-FAST | 先跑相关测试；文档、合同或 API 修改跑 ReleasePipelineTests 与 ProjectContractValidationTests |
| VERIFY-FULL | 锁定还原、Debug/Release 构建测试、格式；两配置零警告零错误、全测通过、格式无差异 |
| VERIFY-API | QualityGatesPassOnThisRepository：基线满足[冻结合同](冻结合同.md) |
| VERIFY-CONTRACT | HostProjectContractPassesOnThisRepository：版本/manifest 一致、声明链接有效、REQ 唯一且验收方法存在 |
| VERIFY-BOUNDARY | HostArchitectureTests、RuntimePipeServerTests：宿主所有权及 runtime 白名单 |
| VERIFY-FRONTEND | FrontendRegistrationTests、ModuleHostContextTests、CommandBusRemoteValidationTests：宿主总线封口、唯一前端、确认回落、界面线程编组、宿主唯一日志与远端路由不重复回显（REQ-HOST-001/003/004） |
| VERIFY-CLI | CommandLineEntryTests、OfflineCommandRunnerTests、RuntimePipeServerTests：通道、隔离、握手、批准与退出码 |
| VERIFY-TRANSACTION | 技术合同 REQ-TXN-001、REQ-REL-001 的包与发布恢复用例 |
| VERIFY-STARTUP | REQ-MOD-005/006/008/009/010 的生命周期用例 |
| VERIFY-REDACTION | REQ-CMD-014、REQ-CFG-001 的脱敏及配置用例 |
| VERIFY-PROCESS | REQ-REL-002 的双流、超时与日志用例 |
| VERIFY-CI | 根 .github/workflows/historyvulcan-freeze-gate.yml 只执行还原、构建、测试、格式与 API/合同校验 |
| VERIFY-DEPLOY | 另行授权后核对发行版本、清单/SHA、消费模块及真实 UI |

精确行为及验收方法只在[技术合同](技术合同.md)定义；门禁解析 REQ 标题和「验收」标记，不对历史文本及 API 删除记录做关键词清零。

## 本地执行

```powershell
dotnet restore .\HistoryVulcan.sln --locked-mode
dotnet build .\HistoryVulcan.sln -c Debug --no-restore
dotnet test .\b-Code-Tests\HistoryVulcan.Tests\HistoryVulcan.Tests.csproj -c Debug --no-build --no-restore
dotnet build .\HistoryVulcan.sln -c Release --no-restore
dotnet test .\b-Code-Tests\HistoryVulcan.Tests\HistoryVulcan.Tests.csproj -c Release --no-build --no-restore
dotnet format .\HistoryVulcan.sln --verify-no-changes --no-restore
```

API/合同门禁已包含在全测中；定向运行可加 `--filter "FullyQualifiedName~ReleasePipelineTests|FullyQualifiedName~ProjectContractValidationTests"`。

测试使用隔离临时目录和唯一名称管道，删除只限自建临时目录，锁文件模拟后释放句柄；不启动/停止正式宿主或修改 AppData。事务断言必须覆盖完整载荷、原始 data 及 Attached/命令快照，不能只看 manifest 存在。故障覆盖暂存、目录锁、备份、接入、数据复制、恢复和提交后清理；配置/内部调用测试同时验证既有值和 Data 语义。

## 发布与真机边界

普通源码验证不调用发布命令或写 z-Publish。候选构建须显式 worktree，省略属于正式流程；宿主禁止 dev.start/submit/finish，自替换由人工在已停止目标的目录外操作。

5.4.0 是消费模块二进制不兼容的升级：Aurora 1.22.0、Janus 5.8.0 要求宿主不低于 5.4.0，旧宿主上会因缺少 RegisterFrontend / RequestConfirmation 接入失败；Aurora 1.21.x、Janus 5.7.x 在 5.4.0 宿主上写总线开关会被拒绝。部署须宿主与这两个模块同批切换。

正式部署后另验 Aurora 前端登记（Ask 命令弹窗、Minerva 窗格在 Aurora 界面线程创建、vulcan.app.show/hide 中继）、真实 WPF 卸载后前端撤销、host.ready 页面发现及 Portunus 传输/配置消费。图形观察遵循 AGENTS 的 Diana windows/capture 流程，实际读取 PNG 并保留尺寸、捕获方式和 SHA。单元测试不能替代真机结果；未执行项目必须明确记录。

此前结果见[5.3.0 重构说明](宿主重构说明.md)、[5.3.0 清理证据](../history/5.3.0-修复与清理证据.md)、[5.2.1 合同归档](../history/5.2.1-现行合同归档.md)。
