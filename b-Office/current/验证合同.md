## 验证原则

- 命令权威声明位于根 `project.manifest.json`；本文解释验证层级、环境和证据。
- 3.0.3 冻结门禁不得因 runner 差异而删除或弱化测试；3.1.1 至 3.3.2 新增合同不得绕过冻结门禁。
- **门禁只验证本仓库自身。** 依赖其他项目实现（HistoryMercury 等）的联调用例归各自仓库；
  本仓库的解决方案与 CI 不得出现跨仓库 `ProjectReference`（DEC-023）。
- CI 验证源码与冻结合同，不执行正式发布、打标签、推 NuGet.org 或消费方部署。
- 本仓库是独立 git 仓；门禁不得把邻接编号目录当成同一仓的其它分支。
- 未执行、失败、偶发失败和不适用必须分别记录；重跑通过不得抹去首次失败原因。

## CI 合同

- 触发：推送到本仓库默认分支 `main`，或 `workflow_dispatch`。
- Runner：`windows-latest`，超时 30 分钟，仓库权限只读。
- 工具链：`global.json` 固定 SDK 9.0.315；官方 Action 使用 Node 24 兼容主版本。
- 顺序：锁定还原、Debug build/test、Release build/test、格式、公开 API、失败摘要、TRX 上传。
- 失败证据：`Write-TrxFailureAnnotations.ps1` 将失败用例和错误首行写入注释与 job summary；
  `historyvulcan-test-results` 制品保存 Debug/Release TRX。
- 边界：候选构建不访问邻接项目仓库、不写正式发布目录；正式提升只由 Diana 事务执行。

## 环境前提

- Windows 10/11 或 GitHub Windows runner；WPF 测试需要 STA/Dispatcher 支持。
- .NET SDK 9.0.315；目标运行时为 .NET 8。
- NuGet 仅使用仓库 `nuget.config` 声明的 nuget.org；还原必须使用锁文件。
- 本机 CET 不兼容时可设置 `DOTNET_EnableWriteXorExecute=0`；CI 不携带该机器特例。

## MCP 与命令总线专项

- 独立前端必须是 `EnableMcp=false`，后台组合必须同时持有完整 MCP 命令组、`McpGateway` 和模块注册表。
- 首次远程目录只能在同步模块装载后开放；坏模块可隔离，但不能先发布一份仅框架命令的中间目录。
- 真实 HTTP `tools/list` 至少覆盖四个代表模块域，`tools/call` 必须实际进入同一后台总线；注册/注销后
  目录动态变化且 MCP 监听实例与端口保持不变。
- `readonly/standard/hidden`、危险确认、前端显式 opt-in、硬排除、审计脱敏与确认超时继续由
  `McpSecurityTests` 覆盖。
- 候选审计必须同时核对注册总数、策略过滤后的 `tools/list` 分组数量和四模块只读实调；模块命令能列出但
  运行时依赖缺失（例如 Minerva Worker）仍视为部署阻塞，不得只按 `isError=false` 判定通过。
- `web.ratelimit=10` 时，认证本机 Shell 连续 25 次控制请求不得 429；普通鉴权 Web 会话第 11 次应返回
  429、`Retry-After` 和 `retryAfterSeconds`。失败鉴权按 IP 的既有测试必须继续通过。
- 专项结论与残余风险见 [项目概览](项目概览.md) 的「命令总线运行事实」。
