## DEC-065 5.6.0 大段结果降到 Debug，控制台在 Info 档位上是一张菜单

2026-09-19：用户要求先查清「级别是模块声明的还是宿主定的」，再据此决定改哪一层；核对后是宿主定的，
遂授权改宿主。

核对依据是三天真机日志（shell-20260917～19）按类别与命令名的统计：Info 级的量几乎全部来自
`cmd:result:*`。`vulcan.command.list` 一项三天 8.2 MB / 6.7 万行；各模块 `*.ui.data`、`*.ui.describe`、
`*.ui.actions` 约 2 MB，其中 janus 单条最大 38 KB、juno 与 aurora 53 KB、cet4 49 KB，都是**一行** JSON。
这些是页面取数的机器面载荷，人不读、消费方也不从控制台读。

- 级别不可能由模块声明：`CommandResult` 只有 Success / Message / Data，`Progress<string>` 也只有一行文本；
  `result.Success ? Info : Error` 从第一版起就写死在 CommandBus 里。因此没有「反向扫出超长消息、
  让模块把自己那条注册成 Debug」这条路可走，规则只能长在总线上。
- 也不采用按域或命令名列白名单：今天列全了，下一个模块的 `*.ui.data` 照样刷屏。改按消息形状判。
- 大段结果在 Info 上留一行提要而不是整条消失：控制台的每一行要仍然答得出「这条指令做完了没有」。
- 失败不降级。要消灭的是看不见人要读的那几行，不是看不见出了什么错。

已知代价（明确接受）：人手敲 `vulcan.command.list` 时，Info 档位上只剩「✓ 命令集: 249 / 249 条（另有 249 行…）」，
整张表要切到 Debug 或去命令集页面看。纯增量行为变化，走次版本 5.6.0，冻结线保持 v5.4.0；公开 API 一个字没动，
模块不必跟版。

行为见技术合同 REQ-HOST-005。

## DEC-064 5.5.0 宿主日志是唯一的控制台日志

2026-09-14：用户选定「改宿主 + Aurora」（而非只让 Aurora 读日志文件），并定下原则：以后所有命令执行的日志，不论哪个模块，
全部走控制台；控制台不在前端另跑一份输出。授权宿主发版部署。

起因：HistoryApollo 0.3.0 把每轮模型调用写进 `CommandContext.Progress`，服务端 `shell-*.log` 里完整记着，Aurora 控制台却一行不见。
核对后是结构性缺口：Aurora 界面总线经 RemoteExecutor 把命令交给宿主总线，只拿回最终回执；宿主总线的回显与进度只写宿主 ShellLog，
控制台却只订阅 Aurora 自建的 MemoryShellLog，宿主又不向模块公开日志。经宿主执行的所有指令（含 Minerva 自己的进度行）都受影响，并非 Apollo 引入。

- `IModuleContext` 新增带默认实现的 `Log`，宿主上下文返回宿主总线的那一个 IShellLog。Aurora 的控制台与界面日志改用它，不再自建第二份。
- CommandBus 把命令交给 RemoteExecutor 时本地不再回显与记结果：共用一份日志后两边各记一遍就是重复，且本地注册表不认识远端命令、无法脱敏。
- 纯增量公开 API 加一处行为收紧，走次版本 5.5.0，冻结线保持 v5.4.0。旧 Aurora 1.22.x 在 5.5.0 宿主上照常接入，只是界面发往宿主的命令在它自己的控制台里不再有回显，须与 Aurora 1.23.0 同批部署。
- 不采用「宿主把日志转交前端、前端再抄一份」：那仍是两份日志。也不采用读日志文件：绑死路径、格式与轮转。

行为见技术合同 REQ-HOST-004。

## DEC-063 5.4.0 总线前端单一所有权与宿主内部面收回

2026-09-14：用户明确指定 5.4 并授权跨模块一次改到位。这是常规需走主版本的兼容变化的例外，不作为后续删除先例。

依据是对运行区 8 个已部署模块做的元数据与 IL 调用点核对：宿主总线的 FrontendExecutor、Confirmation、ConfirmationRouter、UiContext、RemoteExecutor、ShouldUseRemoteCommand 只有 Aurora 在写，会覆盖宿主缺省的拒绝闸口；Janus 直接读 Bus.Confirmation，确认结果取决于 Aurora 是否已改写；ServiceHost 程序集没有任何模块引用；Services 公开面除模块 Smoke 使用的装载器外，只有 Aurora 与 Janus 零星引用。

- 宿主总线交给模块前封口，上述开关只读。前端经 `IModuleContext.RegisterFrontend(IFrontend)` 唯一登记，模块卸载、热装失败或 Attach 失败时撤销；处理器执行中途确认改用 `CommandBus.RequestConfirmation`。
- ServiceHost 全部类型，Services 的 AppPaths、SettingsService、ShellLog、开发管线入口、OfflineModuleInstall、命令目录注册入口，以及 Core 的 CommandHistory、CommandSelectionState、IDeferredStartupWork、CliExposurePolicy 收回 internal 或删除。ModuleHost 只保留模块 Smoke 需要的装载器面。
- 同轮在模块工作区迁移 Aurora、Janus、Minerva 的消费代码。

精确变更保存在 5.4.0 PreFreeze 基线，消费摘要见[模块 API](../package/模块API.md)。此次授权不含提交、标签、推送、正式发布和重启宿主部署。
