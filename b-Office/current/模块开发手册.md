# 模块开发手册

适用宿主：**6.1.1**。这是模块开发者唯一的长期参考：接入契约、工作区流程、指令自描述规范和观察取证都在这里。新模块从模板仓 `0000-002-ModuleReady` 派生（步骤见该仓 README）。对话根在宿主仓时，模块修改也必须进入 start 创建的 F 盘工作区，不改邻接 Clio 主树。

## 五条硬规则

1. **只有 `agent=grok` 迁根。** 其他 AI 留在当前对话根，按 start 返回的绝对路径改 F 盘；不用 Handoff 或打开文件夹代替。
2. **开发三步只给模块，只走同目录 Console CLI。** `HistoryVulcan.Cli.exe --cli vulcan.dev.start|submit|finish`；禁止走 MCP 或直接调 worktree/release。宿主禁止走这三条。
3. **finish 会删工作区。** grok 先迁到该模块 Clio 主树 main，等成功回执再执行本手册 A–D；其他 AI 不迁根，但对话可见路径不能是待删除工作区。未迁出就 finish，这轮对话作废，不要再迁根补救。
4. **不许停宿主。** 禁止 `vulcan.svc.stop` / `restart`、`vulcan.app.quit` 或杀 `HistoryVulcan.exe`；热重载不关宿主。
5. **第一轮在 submit 成功后停。** 没有人的审批，禁止 finish。

## 日用三步

CLI 位于宿主正式 `z-Publish\host`，须与运行的 HistoryVulcan.exe 同目录。worktree 使用 start 返回的绝对路径或目录名；start 回执末尾已给出填好的 submit / finish 命令，可直接复制。

| 步骤 | CLI 参数 | 结果 |
| --- | --- | --- |
| start | `--cli vulcan.dev.start project=<YYYY-NNN-模块> slug=<问题> agent=<ai>` | 创建分支与 F 盘工作区 |
| submit | `--cli vulcan.dev.submit worktree=<工作区>` | 门禁、构建候选、提交并热装，供人审核 |
| finish | `--cli vulcan.dev.finish worktree=<工作区>` | 审批及 A–D 通过后，复核已提交候选、并回 main、回收工作区并热装 |

查参数用 `--cli vulcan.cli.show name=vulcan.dev.submit`。并行再开工作区传 `confirm=true`。5.7.0 起（REQ-HOST-072/073）：模块由工作区所在项目反查，`name=` 可省、写了须一致；submit 的 `msg=`（不含空格）缺省取工作区名里的 slug，finish 的 `msg=` 被忽略；工作区里的未提交改动就是 submit 要提交的，不再需要 `allowDirty=true`（旧参数仍接受）。`dryRun=true` 只报告计划，不构建、写候选、提交或安装。主树有未提交改动时 start / submit 会警告——它们不在工作区里，不会进本次提交。

## 开工作区

默认路径 `F:\ai工作区\<项目>\<短SHA>-<序号>-<标识>`，分支 `ai/<项目>/<同名>`。序号跳过已有目录和旧分支，相同 slug 再 start 会递增，不删除旧分支。人不要把 F 盘工作区加成 Cursor 主项目。

start 生成不入库的 Directory.Build.user.props，将 HistoryVulcanPackageRoot 指向宿主快照；不要修改隐藏的 worktree.root。

### 仅 grok：搬进工作区

迁根工具会占 main，须按四步临时让开主树；不要跳过迁根或提前把工作区切到 main：

```text
git -C C:\OneHistory\HistoryClio\<模块主树> checkout --detach
# move_agent_to_root → F:\ai工作区\<项目>\<工作区名>
git -C F:\ai工作区\<项目>\<工作区名> checkout ai/<项目>/<工作区名>
git -C C:\OneHistory\HistoryClio\<模块主树> checkout main
```

任一步失败先恢复主树 checkout main。迁根后若目标仓误建了源工作区的 ai/... 分支，立即切回 main 并删除该误建分支。

## 改代码

- 从模板仓 `0000-002-ModuleReady` 起步（已是已发布宿主 DLL 的 HintPath 引用及 `<Private>false</Private>`，离线测试含宿主装载冒烟）；仅联调显式传 `-p:HistoryVulcanSourceAvailable=true`。
- Attach 只做接入；跨模块或完整页面发现工作放 `<域>.host.ready`。窗格使用 Aurora 定义的 ui.* 注解，未装界面模块时 vulcan.ui.* 为未知命令。
- **发布描述由模块自带，不改宿主仓**（5.8.0 起，宿主没有模块登记表）。写在模块仓根 `project.manifest.json` 的 `publish` 节，模块名取 `project.name`：

  ```json
  "publish": {
    "versionProps": "b-Code\\HistoryX\\HistoryXVersion.props",
    "versionProperty": "HistoryXVersion",
    "sourceManifest": "b-Code\\HistoryX\\module.manifest.json",
    "package": { "project": "b-Code\\HistoryX\\HistoryX.csproj", "files": ["HistoryX.dll", "HistoryX.xml", "module.manifest.json"] },
    "validation": [{ "tool": "dotnet.exe", "arguments": ["run", "--project", "b-Code\\HistoryX.Tests\\HistoryX.Tests.csproj", "-c", "Release", "-p:NuGetAudit=false"], "description": "Run HistoryX offline tests" }]
  }
  ```

  可省略：`snapshotManifest`、`identityProperty`、`candidateDirectory` / `formalDirectory`（`z-Publish`）、`package.publishTargetFramework`；`validation[].configurations` 写了就按每个配置跑一遍并替换 `{configuration}`。6.1.0 起 `packageDocuments` 不再读取（写了也被忽略，顺手删掉）。改描述和改代码一样在工作区里改，submit 用工作区里的那份。促级校验 csproj/Version.props、源 module.manifest.json 和生成快照的身份版本；根 project.manifest.json 的 version 同步。
- 跨仓路径用代码文本，不写相对 Markdown 链接，F 盘工作区不在 Clio 兄弟目录。
- submit 前跑 `diana.docs.audit domain=<本模块域>`，新加或改过的指令必须零缺陷（见下节）。

## submit

`worktree=` 必填，缺少即拒绝。成功须确认「已热重载到活宿主」且紧跟一行「已核对：<模块> <版本> 已接上宿主，N 条指令」（REQ-HOST-074）；模块没接上、仍是旧版本时 submit 直接失败并给出首条原因。活宿主不可达则失败，不降级。同版本重试可覆盖该工作区候选，finish 复用这个已提交候选。

核对运行状态见「观察取证」；Diana 不可用时：

```text
HistoryVulcan.Cli.exe --runtime vulcan.module.list --format json
```

读 data 或 runtimeAck.modules：目标 instanceId 已变（版本可不变），Aurora 的 commandCount 不得为 0；不要只看 moduleInstanceIds。不要单独 install/reload，尤其全量 reload 会拆除全部模块。门禁失败后修复再 submit，只有期望过时才改门禁期望。

## finish

先获审批，再完成 A–D，**把全部检查输出保留在本轮对话**。工作区指 `F:\ai工作区\<项目>\<工作区名>`，主树指 `C:\OneHistory\HistoryClio\<该模块主树>`。

```text
# A. 对话可见路径：grok 必须已迁到该模块主树并取得成功回执。
#    其他 AI 必须不在待删除工作区；另一工作区或主树可通过。

# B. 工作区完整且仍登记
git -C "<工作区>" rev-parse --is-inside-work-tree   # true
git -C "<主树>" worktree list                     # 含目标 F 盘路径

# C. 已提交，无遗留修改
git -C "<工作区>" status --porcelain              # 空；有输出先 submit

# D. 分支正确
git -C "<工作区>" branch --show-current           # ai/<项目>/<工作区名>
git -C "<主树>" branch --show-current             # main
```

通过后执行日用表中的 finish。已有提交候选、与 main 齐平的闲置工作区也用它回收，分支一律保留。Diana 不 push、不建 PR；热装失败不回滚已成功提交。

对话根仍在目标工作区或目录已半删时，不得调用 finish。若发生占用删除或迁根报 not a git repository，本轮作废，由人关闭并在模块主树 main 新开对话；不要继续迁根补救。

## 指令自描述就是说明书

一个模块对外只有两个面，各写在一个地方：

| 面 | 消费方式 | 写在哪 |
| --- | --- | --- |
| 指令面（总线、MCP、CLI、界面） | 执行 `<域>.<类>.<方法>` | **只写在注册时的 `CommandDescriptor`**，Diana 现查渲染；不另写文档 |
| 代码面 | 引用 `*.Contracts.dll` 调纯函数 | **XML 文档注释**，随包分发 `<模块>.Contracts.xml`，IDE 里直接可见；公开类型缺 summary 由本模块测试拦 |

### 怎么写

- **名字**三段式 `<域>.<类>.<方法>`，域取模块名去 History 前缀（HistoryJanus → janus）。两段名 `<域>.<方法>` 是无类直接方法（如 `mercury.go`），只在确实不属于任何类时用，说明书单列「(直接方法)」组。
- **Summary** 一句话说清做什么、给谁用，120 字内；细节下沉到参数说明。
- **每个参数的 Description** 让调用者照着就能填：格式、单位、范围、例子（例如「已登记工作树名称，例如 2026-020-HistoryJanus」，而不是「项目名」）。
  有限取值写进 `AllowedValues`（总线据此校验），不要只列在说明文字里；可省略的布尔参数写 `Default`（省略本身有含义时——如「省略时查询当前值」——不写 Default，在说明里写清，否则总线代填会把查询变成设置）；必填参数不带 `Default`；位置参数从 0 连续编号。
- **Example** 有参数就必须有，且照抄能跑：带全部必填参数、只用已声明的参数、枚举值在取值内。
- **Readonly / Level / HiddenReason** 如实标：改持久状态就不是只读；执行前要人点头用 `Level=Ask`；不对远端暴露写出具体理由。
- 自描述装不下的东西——返回的 Data 结构、失败与并发边界、跨指令的使用顺序——写进本模块 `b-Office/现行约定.md`（Diana 写在 `b-Office-Diana/现行约定.md`）；Data 若是 JSON，字段只增不减。

### 怎么查

- 读：`diana.docs.catalog`（全部域、所属模块、各类指令数）→ `diana.docs.read domain=<域> [class=<类>]` 或 `diana.docs.read command=<完整指令名>`。
  正文在 `data.manual`，来源是活宿主 `vulcan.command.list`，新模块装上即可查。
- 自查：`diana.docs.audit [domain=<域>]` 按规则列出缺陷（缺示例、示例与参数对不上、参数说明过短、取值写在文字里、默认值矛盾、引用已退役文档等）。
  submit 前本模块新增或改过的指令必须零缺陷。
- Diana MCP 工具未暴露或调用失败时，先把具体原因写进对话，再改用 MCP 的 `vulcan.command.list domain=<域>` / `vulcan.command.show name=<指令>`（同一份注册表）；
  禁止打开邻接项目的 office 或 worktree 去猜接口。

## 文档

模块的长期文档只有一份，直接放在 office 文件夹里：`b-Office/现行约定.md`（Diana 为 `b-Office-Diana/现行约定.md`）。只写代码看不出来的取舍、真机才知道的事和已知缺口。

| 要知道的 | 去哪看 |
| --- | --- |
| 指令怎么调用 | `diana.docs.read domain=<域>` |
| 代码面 | `<模块>.Contracts.xml` |
| 页面组件 | `aurora.component.show name=<名>` |
| 实现细节 | 调用处注释 |
| 行为是否成立 | 本模块测试 |

## 接入契约

宿主提供模块注册、命令总线和开发/发布管线；界面归 Aurora、工作台/快捷键归 Mercury、Web/MCP 归 Portunus。本节是宿主对模块的代码面，Core 公开类型白名单由 `UnifiedContractCloseoutTests` 守住。

### 引用与兼容

模块**只引用契约程序集** `z-Publish/host/HistoryVulcan.Core.dll`，设 `<Private>false</Private>` 并在构建前验证目标存在；测试工程反过来设 `Private=true`。
不引用 `HistoryVulcan.Services` / `ServiceHost`，不向宿主程序集开放 internals。源码联调须显式开关，不自动回退到宿主 ProjectReference。

**宿主给模块的只有「一条总线 + 一个上下文」**。Core 的公开类型就是下面这张白名单，多一个即测试失败；Services、ServiceHost 没有公开类型。

| 类型 | 用途 |
| --- | --- |
| `IModuleContextAware` / `IModuleContext` | 模块入口与宿主给的上下文 |
| `ICommandBus` / `ICommandRegistrar` | 窄总线：执行、安静执行、中途确认；只能加指令的登记口 |
| `IModuleLog` / `ModuleLogExtensions` / `ShellLogLevel` | 宿主那一份日志，只写 |
| `IModuleEnvironment` / `HostRunMode` | 数据目录、包目录、运行方式、宿主版本 |
| `BusEvent` | 总线事件 |
| `IFrontend` | 界面模块实现的前端角色 |
| `CommandDescriptor` / `ParameterSpec` / `ParamType` / `CommandLevel` / `CommandContext` / `CommandResult` | 指令定义、参数与回执 |
| `CommandParser` / `ParsedCommand` / `CommandSyntaxException` | 指令文本的解析与引号转义 |
| `ModuleDomainNaming` | 模块名 → 指令域的规则（主题前缀也按它） |
| `BuiltinCommandDefinitions` | 前端角色的共享指令定义（`vulcan.command.help`、`vulcan.app.get/set`） |
| `ModuleInfoBase` / `ModuleCommandAttribute` | 模块身份与反射指令元数据 |

6.0.0 是主版本：5.x 编译的模块包在 6.x 宿主上一律接不上（`MissingMethodException`）。收回了哪些类型、各用什么替代见[有效决策](有效决策.md) DEC-071 与 `b-Code-Eng/public-api-baselines/<版本>/`。
测试里要登记口或总线，自写 `ICommandRegistrar` / `ICommandBus` 替身（模板与各模块仓的 `ModuleTestHost.cs` 是现成写法）；真实装载与执行以 `--probe` 为准。

### 模块入口与上下文

| 成员 | 说明 |
| --- | --- |
| `Bus` | `ICommandBus`：`ExecuteAsync(text, source)` 执行（回显、确认、结果进宿主日志，发 `vulcan.command.executed`）；`InvokeAsync(text, source)` 安静执行（不回显、不记结果、不发事件，确认闸口照旧，取数用）；`RequestConfirmation(prompt)` 处理器执行中途要确认 |
| `RegisterCommands(Action<ICommandRegistrar>)` | 把本模块指令暂存进当前快照，提交时一并登记，随模块卸载撤销 |
| `Log` | 宿主那唯一一份日志，只写 |
| `Environment` | `ModuleName`、`DataDirectory`、`PackageDirectory`（本包槽位，只读）、`RunMode`、`HostVersion` |
| `Subscribe(topic, handler)` / `Publish(topic, payload)` | 总线事件 |
| `RegisterFrontend(IFrontend)` | 登记唯一前端 |

`Log`、`Environment`、`Subscribe`、`Publish`、`RegisterFrontend` 带默认实现：模块自写的上下文替身不覆盖时调用抛 NotSupportedException。

**来源由宿主盖章**：经 `context.Bus` 的调用，宿主把模块给的 `source` 包成 `module:<模块名>:<source>`（空串时为 `module:<模块名>`）。模块在自己的处理器里再发指令时，传最里面那层标签即可，别把收到的整串原样转交（会叠章）。
运行包变更（`vulcan.module.install/remove/uninstall`）只接受本机可信来源：没有内层的 `module:<名>` 可信；有内层就按最里面那层判，所以网关转进来的远端请求（`module:HistoryPortunus:MCP:<客户端>`）不会因为外面套了模块章就变成可信。

宿主先发现程序集，再逐个 Attach，成功一个才发布其命令。`dependsOn` 是模块名数组，只约束次序，例如 `{"dependsOn":["HistoryAurora"]}`；缺失、环或自依赖只记诊断。无依赖及环内按名称排序。
Attach 时只有此前成功模块的命令可见，不应在此跨模块调用或拉全量页面目录。需等全宿主完成的工作登记 `<域>.host.ready`：整轮结束经安静通道调用一次，不进历史；未登记跳过，单包热装不触发。`vulcan.module.ready` 可查询装载是否结束及未接入名单，不能以延时重试代替就绪信号。
Attach 失败时该模块全部命令不可执行；冷启动保留诊断并继续，热安装失败回滚。同内容包仅在 `Attached=true` 时是幂等成功，失败或未装载实例可重装修复。

**前端登记**：同一宿主只允许一个前端。另一模块已登记时 `RegisterFrontend` 抛 InvalidOperationException；同一模块重复登记替换旧登记。释放句柄、模块卸载、热装失败或 Attach 失败时宿主撤销登记，确认回到宿主缺省（拒绝）。
登记期间：`Level=Ask` 的命令由前端确认；`RequiresUiThread` 命令编组到前端的 `UiContext`；`vulcan.app.show / hide / close / focusconsole` 与 `vulcan.app.quit` 的关窗步骤转交前端的 `ExecuteAsync`。
前端自己的指令照常经 `RegisterCommands` 登记，要碰窗口的声明 `RequiresUiThread`；不要自建第二套总线或把指令抄成代理再登记。`vulcan.command.help`、`vulcan.app.get/set` 宿主已登记同名时前端不再登记。

**宿主日志**：`IModuleContext.Log` 是宿主唯一一份日志，总线上每条指令的回显、进度与结果都写在这里并落盘。**控制台只显示这一份**，界面模块不得另建日志来显示命令输出；模块自己的运行日志也写进来（类别以本模块指令域开头）。
日志类别是契约的一部分：回显 `cmd:<来源>`、进度 `cmd:progress:<域>:<类>`、结果 `cmd:result:<域>:<类>`、总线内部故障 `cmd:internal`、事件中枢诊断 `bus.event`。成功结果单行且不超过 200 字进 Info，多行或超长时 Info 只留提要、正文进 Debug；失败整条进 Error。
要让人看见长任务的过程，在处理器里写 `CommandContext.Progress`，不要等结束后在回执里汇总；经 Bus 调用别的模块时，对方的过程由对方自己写，调用方不复述。

### 统一契约速查

| 需要 | 用这个 | 不要 |
| --- | --- | --- |
| 执行指令、中途确认 | `context.Bus.ExecuteAsync` / `RequestConfirmation` | 自建总线或注册表 |
| 取数（不是操作） | `context.Bus.InvokeAsync` | 为了不刷控制台而绕过总线 |
| 可写数据目录 | `context.Environment.DataDirectory`（`%AppData%\HistoryVulcan\ModuleData\<模块名>`，装包/热装/卸载都保留，`uninstall purge=true` 才删） | 自己拼 `%AppData%` 路径、写进包槽位 |
| 随包发布的文件 | `context.Environment.PackageDirectory`（只读） | 从宿主数据根推 `Modules\<名>`、用 `Assembly.Location`（内存流装载时为空）、往槽位里写 |
| 运行方式 | `context.Environment.RunMode`：`Service` / `OfflineCli` / `Probe` | 读进程名或进程参数 |
| 宿主版本、项目库、工作区根、运行区、宿主可执行文件 | 执行 `vulcan.host.info` | 按进程名找宿主、写死 `2026-023-HistoryVulcan/z-Publish` |
| 指令目录、单条详情、模块列表 | 执行 `vulcan.command.list` / `show`、`vulcan.module.list`，按 JSON 字段名读 Data | 强转宿主的 C# 类型 |
| 输入校验、未知指令建议、目录版本 | `vulcan.command.validate text=`、`vulcan.command.suggest name=`、`vulcan.command.revision` | — |
| 目录/模块/执行/日志变化 | `context.Subscribe`，见下表 | — |
| 通知别的模块 | `context.Publish("<本模块指令域>.<事件>", 载荷)` | 写文件让对方去读 |
| 装载冒烟 | `HistoryVulcan.Cli.exe --probe <包目录> --cli "<指令>" --format json` | 在测试里构造宿主类型 |

宿主发布的主题（载荷为 JSON，字段只增不减）：

| 主题 | 载荷 | 说明 |
| --- | --- | --- |
| `vulcan.catalog.changed` | `{ revision }` | 指令目录变了；去抖，一轮装载只发一两次 |
| `vulcan.module.changed` | `{ modules: [{ name, version, attached, commandCount }] }` | 模块清单变了（整轮重载、单包装卸都经这里） |
| `vulcan.command.executed` | `{ name, source, success, summary }` | 一条指令执行完；不含指令全文与 Data |
| `vulcan.log.entry` | `{ time, level, category, message }` | 宿主日志新增一行；**订阅方不要把它再写回日志**，否则绕圈 |

事件规则：主题是小写点分段、至少两段；订阅可用 `前缀.*`。每个订阅按发布顺序串行收到事件，处理器在线程池上运行，抛出的异常只记日志。事件是通知不是调用：要细节就再执行只读指令。模块只能发布以自己指令域开头的主题；模块卸载时它的订阅自动退掉。

`--probe` 把包复制到临时运行区装载（manifest `dependsOn` 里正式运行区已有的包一并复制），数据目录也在临时目录，`RunMode = Probe`；输出是否接上、指令数、附着失败与发现诊断，给了 `--cli` 就再执行那条指令。退出码 0 接上且指令成功，1 没接上或指令失败，2 用法错误。

### 宿主指令的 Data

宿主自己的指令，Data 一律是 `JsonElement`，字段名驼峰；**契约是这里写的 JSON 形状**，字段只增不减，消费方按名取字段、忽略不认识的字段。模块自己的指令 Data 由模块自定（同进程可传活对象，由调用方管理类型与生命周期；形状写进该模块的现行约定）。

`vulcan.command.list` 的每一行（`show` 的 `command` 也是这一形状）：

```jsonc
{ "commandName": "janus.proj.list", "domain": "janus", "commandClass": "proj", "method": "list",
  "summary": "…", "example": "…", "parameterCount": 1,
  "source": "module", "sourceDetail": "HistoryJanus",        // 宿主自身为 "framework:service"，sourceDetail 为 null
  "dangerous": false,                                        // 级别为「询问」
  "requiresConfirmation": false, "requiresUiThread": false, "readonly": true,
  "hiddenReason": null, "allowUnspecifiedParameters": false,
  "parameters": [ { "name": "…", "type": "string|int|double|bool", "required": true,
                    "default": null, "position": 0, "allowedValues": [], "description": "…" } ],
  "annotations": { "ui.page": "…" } }
```

| 指令 | Data |
| --- | --- |
| `vulcan.command.show name=` | `{ command: <行>, parameters: [...], annotations: {...} }` |
| `vulcan.command.domains` | `[ { domain, count } ]` |
| `vulcan.command.validate text=` | `{ ok, name, usage, error? }` |
| `vulcan.command.suggest name=` | `[ "<指令名>" ]`，最多 5 条 |
| `vulcan.command.revision` | `{ revision }` |
| `vulcan.module.list` | `[ { moduleName, description, author, version, open, assemblyFile, commandCount, slot, ui, instanceId, sourcePath, manifestPath, attachFailures: [], dataDirectory, attached } ]` |
| `vulcan.host.info` | `{ version, runMode, libraryRoot, worktreeRoot, modulesRoot, moduleDataRoot, dataRoot, hostExecutable }` |
| `vulcan.log.recent count=` | `[ { time, level, category, message } ]`，与 `vulcan.log.entry` 同形，取最新的若干条 |

`vulcan.command.validate/suggest/revision`、`vulcan.log.recent` 对 MCP 隐藏，供前端与网关经总线调用。

### 命令契约

命令声明 Name、CommandClass、Summary、Handler；有输入时给 Parameters 与 Example（写法见上节）。能在执行前决定的确认用 `Level=Ask`，执行中途才知道的用 `Bus.RequestConfirmation`，不要自取确认通道。写了 ConfirmPrompt 就必须 `Level=Ask`，否则登记时拒绝。Annotations 由消费方解释；处理器不直接操作宿主窗口、模块槽或源码目录。

总线固定当次命令定义及敏感值，在回显、历史、结果、异常和进度中脱敏（参数名以 token/password/secret/privatekey/connectionstring 结尾或为 code；`vulcan.app.set` 敏感键的值），执行中注销/替换不影响该请求。`InvokeAsync` 不回显、不入历史，Data 保留原始载荷但进度仍脱敏；需要原值时读 Data，不解析回执文本。模块自行写日志也须自行脱敏。

### 模块包与装卸

候选在 `z-Publish/HistoryX-vX.Y.Z/`，只包含 module.manifest.json、模块程序集/XML、`package.files` 声明的其余文件和 SHA256SUMS（6.1.0 起没有 `docs/`）。项目/版本 props、源 module.manifest.json、根 project.manifest.json 的身份版本须一致。

运行区固定为 `%AppData%\HistoryVulcan\Modules\<模块名>`，只发现直属完整包，不扫描裸 DLL。SHA 清单覆盖槽位里的全部文件，只有包内发布归档 history/ 不计入。模块不得手工拷 AppData 或改变发现根。槽位是只读的：装包整槽替换、不带旧文件；模块往槽位里写任何东西，下一轮发现就会因清单不符判为坏包。

安装先校验、同卷暂存、卸载同名实例、备份并替换，只将该包装回快照。失败恢复原包；恢复失败保留备份并返回路径。`vulcan.module.unload` 只移除内存实例和命令；`vulcan.module.uninstall name=` 删除完整运行包，数据目录默认保留，`purge=true` 一并删除。模块开发通过 submit/finish 热装，避免全量 reload 拆掉全部模块；离线写 AppData 不算活宿主热重载。

### CLI 通道

使用与运行宿主同目录的 `HistoryVulcan.Cli.exe`：`--cli` 固定离线组合（`RunMode = OfflineCli`），语法和白名单校验在组合前完成；`--probe` 测试装载一个候选包；`--runtime` 只连接活宿主，不可达即失败，动作还须 `--approve`。runtime 仅放行 `vulcan.module.list/ready/reload/install`，reload/install 要求批准。宿主自身使用 `vulcan.release.cycle`。

`--format json` 使 stdout 仅含一个结果对象：runId、success、exitCode、executionTarget、candidatePath、installedPath、runtimeAck、logPath、diagnostics、data。exitCode 与进程退出码一致：成功 0，普通失败 1，语法/用法错误 2，runtime 不可达 3。工作区候选可覆盖同版本，主树正式促级拒绝内容不同的同版本覆盖。

## 观察取证

开发管线只管「怎么走」，Diana 补「怎么看」。Diana 不开工作区、不提交、不装模块，`diana.host.*` 只读装载状态；`diana.*` 不属于开发管线，不传给 --cli/--runtime。

### 推荐：一次取基线，一次比较

```text
diana.host.observe name=<模块>
# 保留返回的 baselineToken；submit 成功后：
diana.host.observe name=<模块> baseline=<原样传回令牌>
```

返回模块全表、ready、日志和 comparison：`instanceChanged` 核对目标实例，`changes` 里的 Regression 标记指令数下降、附着退化或模块消失。要同时看 errorCount、regressionCount 和 issues——issues 为空只说明证据完整，不表示没有错误；成功回执只表示取得了观察结果，不表示验收通过。令牌由调用者保留，Diana 自身热重载后仍可比较。

这是分次只读快照（atomic=false），管线阶段没有数据源（pipeline.status=unavailable），仍须核对 submit 的 CLI 回执；不要用 ready 推断 submit 完成。`logsComplete=false` 表示证据不全（前端重启、缓冲缺口、截断或提供者不可用）：保留原基线，用 `diana.log.read` 的 nextAfter 翻页，不要换新令牌跳过遗漏的错误。

### 一轮里的三处

| 时机 | 做什么 | 指令 |
| --- | --- | --- |
| 改代码之前 | 取基线 | `diana.host.observe name=<模块>`；改界面加 `diana.view.windows` → `diana.view.capture` |
| submit 成功之后 | 核对判据 | `diana.host.observe ... baseline=`，或分开查 `diana.host.ready`、`diana.host.modules`、`diana.log.read after=<基线> minlevel=error` |
| 卡住时 | 先定位再动手 | 见下表 |

submit 的成功判据：回执含「已热重载到活宿主」、该模块 `instanceId` 已变（同版本覆盖时版本字符串可以不变）、其它模块（尤其 Aurora）的 `commandCount` 不得变成 0。
单项取证要留在对话里的值：`diana.log.read` 的 `newestSequence`（本轮基线）与 `frontendInstanceId`（变了说明前端重启过，旧 `after` 作废，改用 `since=<ISO 时间>`）；目标模块的 `instanceId` 与 `version`。

判读要点：`diana.host.ready` 为 false 只说明还在装，重查，别据此回滚。`attachFailures` 非空 = 装进去了但 Attach 抛了异常，原文就在返回里，不必翻宿主日志。`diana.log.read` 只覆盖 Aurora 前端控制台缓冲，宿主装载日志不在里面；`truncated=true` 只表示本次结果不完整，用 `after` 翻页。

| 症状 | 先用 | 判据 |
| --- | --- | --- |
| 重载后模块没出现 | `diana.host.modules` | 全表里有没有它；有则看 `attached` 与 `attachFailures` |
| 命令还在但界面没了 | `diana.host.modules name=<模块>` | `attachFailures` 原文；`ui=true` 却 `attached=false` |
| Aurora 指令数变成 0 | `diana.host.modules` | 为 0 交给人，不要自己重载宿主 |
| 前端报错但不知道原文 | `diana.log.read after=<基线> minlevel=error` | 多行异常和堆栈原样返回，不要截图去认字 |
| 不确定别的模块暴露了什么 | `diana.docs.catalog` → `diana.docs.read` | 读指令自描述，不打开邻接源码树 |

### 看界面

只读观察：`diana.view.windows` → `diana.view.capture handle=<句柄>` → **实际读取 PNG**，保留尺寸、捕获方式和 SHA；只记路径不算取证。两次 `Sha256` 完全相同 = 客户区一个像素都没变，这本身就是结论。后台捕获不移动鼠标、不切换前台。

禁止为只读观察调用 Computer Use、点击窗口、移动鼠标或抢占前台。View 失败先记录原因，不得静默降级为 GUI 控制；需接管鼠标/前台或点击、输入、拖拽时先取得用户同意。

### Diana 不可用时

先把具体原因写进对话（工具表里没有 Diana、调用超时、鉴权失败），再降级，不要静默换路子：

- `diana.host.*` → `HistoryVulcan.Cli.exe --runtime "vulcan.module.list" --format json`，读 `data` 或 `runtimeAck.modules`。
- `diana.docs.*` → MCP 的 `vulcan.command.list domain=<域>` / `vulcan.command.show name=<指令>`。
- `diana.log.read` → 多半是 Aurora 未装载或正在热重载；先 `diana.host.ready`，不要读磁盘日志冒充控制台。
- `diana.view.*` → 记录原因；不得因此改用 GUI 控制。

## 卡住时

| 现象 | 处理 |
| --- | --- |
| submit/finish 不返回 | 查宿主日志末尾，不停宿主 |
| stop/restart/quit 不返回 | 正在等人工确认，取消调用 |
| 工作区删不掉 / 迁根报错 | 检查 Cursor 占用及 finish 的 A–D；目录已损坏按 finish 一节的规定重开对话 |
| Aurora 指令为 0 / JSON 没有模块名 | 检查是否误用全量 reload，读 data/runtimeAck.modules |
| 版本门禁不符 | 核对项目、源 manifest 与快照身份 |
| 对宿主调用 start 被拒 | 符合边界，宿主禁止走模块开发管线 |
| 说明书太长 | `diana.docs.read` 加 `class=` 或改用 `command=` |
