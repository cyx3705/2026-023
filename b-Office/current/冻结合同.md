# HistoryVulcan 公开 API 变更合同

源码：**8.0.0**。2026-10-11 按 [DEC-076](有效决策.md) 退役固定冻结标签和逐版本批准基线。文件路径保留供已有链接使用，不再表示当前开发线被冻结。

## 现行校验

宿主给模块的统一契约仍是一条总线（`ICommandBus` / `ICommandRegistrar`）、一个上下文（`IModuleContext`），加上开发/发布总线的命令面。
Core 的公开类型由[模块开发手册](../模块开发手册.md)「接入契约」白名单与测试共同守住；Services 与 ServiceHost 没有公开类型。
三组 `PublicAPI.Shipped.txt` / `PublicAPI.Unshipped.txt` 继续随源码维护，编译分析器核对公开签名，一致性门禁拒绝缺失文件及孤立的 `*REMOVED*` 记录。
CI 与发布管线不再读取 `project.freezeTag`、独立冻结标签表或 `public-api-baselines/<版本>/`。历史基线目录和既有 Git 标签仅保留作版本追溯。

v6.0.0（DEC-071）与 v5.4.0（DEC-063）是历史冻结记录，不限制 V8.0 的契约设计。
界面、Web/MCP 网关和模块领域抽象不属于宿主职责，见[项目概览](项目概览.md)。

## 变更纪律

- 内部重构可以继续；正确性修复保持签名并补回归测试。宿主内部类（总线、注册表、日志、模块宿主）可以随意改，不影响任何模块。
- 新增公开 API 先推进版本，再登记 Unshipped、白名单与消费摘要；通用集成优先使用命令名与事件主题。
- 载荷形状只增不减；删字段、改语义或改签走主版本并提供迁移说明。
- Git 标签和正式发布须明确授权。契约清理不等于发布或部署。

验收按[验证合同](验证合同.md)执行。已部署引用核对不能替代正式发布前的消费模块与真机联调。
