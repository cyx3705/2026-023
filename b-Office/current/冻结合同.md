# HistoryVulcan 宿主冻结合同

当前源码 **5.3.0**；冻结基线 **5.1.2 / v5.1.2**（DEC-056）。
冻结的是模块注册、命令总线和开发/发布消费合同，内部实现可以修复。

## 1. 冻结范围

三份合同程序集为 HistoryVulcan.Core、HistoryVulcan.Services、HistoryVulcan.ServiceHost。
现行公开面由 Shipped 加 Unshipped 增删共同定义；不能单独把历史 Shipped 中已移除成员当成可用接口。
界面、Web/MCP 网关和模块领域抽象不属于宿主冻结职责。

## 2. 变更纪律

正确性缺陷可在保持签名的前提下修复，必须有回归测试。通用能力优先用命令名集成；
新增公开 API 先推进版本，再进入 Unshipped、批准基线和消费摘要。
常规删除或签名变化走主版本并提供迁移说明。冻结标签及正式发布另行授权。

## 3. 5.3.0 批准例外

用户明确批准 5.3.0 清理过期公开面，并保留 v5.1.2 标签，见[DEC-060](有效决策.md)。
本轮删除旧发现、源确认、选择性注册、MCP 专用设置与失效确认入口；
ModuleDiscoveryEntry 去掉 McpExposure 构造参数。完整清单见[消费摘要](../package/模块API.md)。
这不保证未知第三方二进制兼容，已部署消费引用核对不替代正式发布前联调。

三份 Shipped 不修改。5.2 已有移除记录和本轮 5.3.0 记录保存在 Unshipped，并逐项匹配
`b-Code-Eng/public-api-baselines/5.3.0/`。每条 *REMOVED* 必须能追溯到 Shipped。

## 4. 冻结后的宿主职责

模块上下文只提供 Bus 和 RegisterCommands；宿主不因单个模块需要恢复领域接口。
默认确认拒绝，界面接管读取当前确认服务。FrontEnd/Remote 通用委托的保留以实际消费证据为依据，不恢复网关。
固定运行区完整包发现、事务与用户数据恢复属于宿主正确性保证。

## 5. 验收与交付

本仓锁定还原、Debug/Release 构建测试、格式、API 和合同门禁须通过，验证范围见[验证合同](验证合同.md)。
真机联调、正式部署、提交、打标签和推送不在本轮实施范围。不得把源码门禁通过表述成已发布或已重新冻结。
旧冻结过程、计数和版本演进见[历史原文](../history/5.2.1-现行合同归档.md)。
