# HistoryVulcan V8.0 宿主升级书

日期：2026-10-11。状态：已实施首期能力，正在隔离验证；生产宿主替换与真实模块迁移另行安排。

当前源码为 **8.0.0**；固定冻结基线已按 DEC-076 单独退役，公开 API 声明与契约验证继续执行。本书记录 V8.0 首期实现边界与验证依据；不改变生产宿主替换权限。规则编号 `V8-DES-*` 与现行技术合同中的 REQ-HOST-093…097、有效决策 DEC-077 对照。

## 一、升级目标与首期规模

**V7.0 统一模块交付物，V8.0 让多台电脑组成一个逻辑宿主。**

用户当前只有两台电脑，首期按两节点实施。每台电脑运行一个物理宿主，加入同一个逻辑宿主后，共享模块目录与总线访问能力。普通模块的命令域继续指向模块，调用者不需要知道执行电脑的地址。

普通模块可以在所有节点保留包副本，但正常运行时只有一个装载实例。用户决定模块在哪台电脑运行，宿主不因某台电脑断网而自动在另一台电脑装载替代实例。

前端是唯一的模块实例例外：每台电脑装载一个前端，负责本机窗口、界面线程和交互。宿主按前端角色处理该例外，不在源码中写具体模块名或按某个模块域前缀判断。

首期不引入自动故障接管、自动调度、独立协调节点或复杂集群基础设施。云上预装载区承担包存储与获取职责，不必承担宿主通信中转。

## 二、现行基础与读取依据

依据为 [项目概览](项目概览.md)、[技术合同](技术合同.md)、[有效决策](有效决策.md)、[模块开发手册](../模块开发手册.md)，以及以下当前源码：

- [DevPipelineCommands.cs](../../b-Code-HistoryVulcan/HistoryVulcan.Services/Development/DevPipelineCommands.cs)：start、submit、finish。
- [ReleaseCommands.cs](../../b-Code-HistoryVulcan/HistoryVulcan.Services/Development/ReleaseCommands.cs)：门禁、候选、提交与提交后的热装。
- [WorktreeCommands.cs](../../b-Code-HistoryVulcan/HistoryVulcan.Services/Development/WorktreeCommands.cs)：合并、回收工作区与合并后的热装。
- [ModulePackageHotReload.cs](../../b-Code-HistoryVulcan/HistoryVulcan.Services/Development/ModulePackageHotReload.cs)：安装与活宿主附着核对。

现行流程是：

| 阶段 | 当前行为 |
| --- | --- |
| start | 创建模块分支和开发工作区 |
| submit | 门禁、构建候选、提交，再热装到活宿主，供人审核 |
| 审核 | 人检查实际运行效果；未通过则继续改并再次 submit |
| finish | 复核已提交候选，合并回 main，回收工作区，再热装 |

因此，**在本项目中，发布与装载紧密结合，是 AI 开发闭环的一部分**。V8.0 应扩展这条管线的交付目标，不另建一套要求用户在版本目录中选包的日常部署流程。宿主自身仍不走模块的 dev.start/submit/finish。

V7.0 的一个 `{模块名}.nupkg` 同时是候选、运行区安装物和装载输入；由宿主在构建后按发布描述生成。采用 nupkg 容器不等于已经采用标准 NuGet 源，也不等于具备云端下载能力。V8.0 继续使用同一包格式。

现行材料有两个需要在实施前单独处理的差异：

1. 手册把 finish 描述为快进合并；当前 `MergeAsync` 在快进失败后还会尝试普通合并。本书不修改该行为，后续须核定并同步合同与实现。
2. 热装核对在无法读取包身份或无法识别模块列表时，会返回成功对象并注明“未核对”。V8.0 的交付结果必须区分安装回执与已证实的附着结果，不能只凭 `Success=true` 宣称目标实例已经运行。

## 三、统一模型

### V8-DES-001 身份与装载归属

| 对象 | 含义 |
| --- | --- |
| 逻辑宿主 | 用户登记并互相连接的一组物理宿主；普通模块在该范围内唯一 |
| 节点 | 一台电脑上的宿主，拥有稳定节点身份；地址变化不改变身份 |
| 模块 | 稳定模块身份及其指令域，保持与现行注册自描述一致 |
| 包制品 | 某次构建产生的 nupkg，由模块身份、版本、内容哈希和发布记录追踪 |
| 装载归属 | 模块应当在哪个节点运行，或当前只存于预装载区 |
| 运行实例 | 某次实际装载产生的实例；与包版本和节点身份分别记录 |
| 前端实例 | 按“节点身份 + 前端角色”定位，每节点至多一个 |

“有包”“归属本机”“已经附着”是三个独立事实。磁盘中存在包不能自动取得执行所有权，缓存同步不能触发装载。

### V8-DES-002 统一交付目标

用户面对模块及其目标，不需要进入各版本目录寻找安装文件。

| 目标 | 管线行为 | 完成证据 |
| --- | --- | --- |
| 本机节点 | 安装、热装并核对 | 目标节点、包哈希、版本、实例、附着及指令数 |
| 另一节点 | 交付包，由对方宿主安装、热装并核对 | 对方宿主的实际回执，不能用发送成功代替 |
| 云上预装载区 | 保存包并登记可获取制品，不启动运行实例 | 云端存储及索引确认、包哈希 |

“装 A、装 B、存预装载区”是同一交付流程的不同目标。选择运行节点后，包仍可保留在云端和各节点缓存中。

默认位置建议：首次发布未指定目标时装在开发电脑；已有运行归属时，后续发布沿用该归属，避免把已经移到远端的模块意外搬回本地。该默认规则是讨论建议，待实施前确认。

## 四、云上预装载区与包同步

### V8-DES-003 预装载区由发布管线维护

开发电脑负责构建并执行发布，云上预装载区负责持久保存可获取的包。预装载区应能被各地节点访问，并在开发电脑关机后仍提供包。

流程为：

```text
start → AI 开发 → submit → 人工审核 → finish
                    │
                    ├─ 上传云上预装载区并登记制品
                    ├─ 同步已连接节点的包缓存
                    └─ 在所选运行节点安装、热装并核对
```

云端供应商和存储协议尚未确定。GitHub Releases、合适的包服务或云对象存储都属于待选实现；须验证与 V7.0 包格式、版本字符串和候选覆盖规则的兼容性。若采用自有服务器，其可达性和在线维护也由部署方案明确。CDN 是下载入口的可选加速能力，每台电脑不需要各自部署 CDN。

包索引至少需要能回答“这个模块当前可获取哪个制品”，内部保留版本、哈希、来源与发布阶段。submit 待审制品和 finish 已收口制品要能辨别，缓存同步不能把待审版本自动促为正式版本。

### V8-DES-004 一次发布同步所有已登记节点

包较小，首期按一次发布向所有已连接节点同步完整包设计。断网节点登记为待同步，下次连接时补齐。仅在云端收到完整包并校验后更新对应索引；节点下载或传输失败不留下可被运行发现识别的半包。

缓存应在运行发现目录之外。V7.0 的 `Modules` 目录变化会触发重载，不能把所有同步包直接放入该目录并期待只装载其中一个。具体缓存目录和配置键在实施阶段确定，不在本文写入机器路径。

工作区候选可以在同版本下重新 submit，因此同步去重必须依据内容哈希和发布记录，不能只比较版本号，也不能按文件时间或版本字符串排序选“最新”。当前正式包不可覆盖、旧发布归档不可变的边界继续有效。

目标运行节点不可达时，发布应明确报告目标交付未完成，不能静默转成本机部署。其他非目标节点离线可以作为待同步状态，不必阻塞目标节点交付。

## 五、开发管线升级

### V8-DES-005 保持发布即交付的闭环

submit 扩展为：现行门禁、构建与提交，云端登记及缓存同步，所选目标的交付和核对，最后进入待审。人应当在 submit 后就能检查目标节点上的实际效果。

finish 复用已提交、已审核的候选及目标，不重新选择一个“最新包”，不静默更换节点。应把本轮目标、制品哈希和审核依据关联到管线记录。若期间装载归属或制品已改变，应报告变化并要求重新审核或明确调整。

针对云上预装载区目标，审核证据是制品及云端接收状态；没有运行实例时，不宣称已经完成运行效果审核。

首次发布默认本机，已有归属默认更新原节点；显式选择其他节点属于迁移，不能绕过装载归属检查。具体新增 CLI 参数、默认值和记录格式尚未确定，本文不提供冒充已注册指令的示例。

### V8-DES-006 分阶段回执与失败恢复

云端、两台电脑和 Git 操作没有共同的本地事务。回执应分别记录：构建与门禁、提交、云端保存、各节点同步、归属变更、目标安装、附着核对、合并与工作区回收。

保持现行边界：submit 在提交后热装，热装失败不自动撤销提交；finish 的合并与回收完成后，即使热装失败，也不能假装这些步骤没有发生。失败结果应带可恢复的制品身份和未完成阶段，避免要求用户回版本目录找包。

向运行节点交付时，整体成功必须有该节点实际核对证据；预装载区目标成功只表示制品已交付，不表示有模块正在运行。重复交付同一制品应可安全重试，但不能把任意写命令当作可重试操作。

## 六、两台宿主的通信

### V8-DES-007 宿主内置直连

```text
电脑 A 宿主 ←──── 一条双向连接 ────→ 电脑 B 宿主
     │                                  │
     └──────── 云上预装载区 ─────────────┘
```

A 提供监听入口，B 主动连接；建立连接后双方都能发起请求。监听者只是连接角色，不因此成为所有模块的运行节点或装载归属裁决者。局域网直接连接，跨地区可通过 VPN 等方式解决可达性。

建议使用带 TLS 的 WebSocket 双向长连接；具体协议、凭据和配对方式待确认。首期无需电脑间 CDN、独立消息中间件或额外协调模块。

连接由宿主维护：节点认证、目录交换、请求转发、进度与回执、事件订阅、心跳、重连和状态同步。Web/MCP 对外网关继续属于 HistoryPortunus。宿主节点协议不恢复通用 Web/MCP 网关，也不要求改造 Portunus 才能建立宿主连接。

### V8-DES-008 总线接口与执行边界

调用路径为：调用节点总线 → 按模块归属路由 → 目标宿主本机总线 → 模块处理器 → 原路返回结果。

保持“一条总线 + 一个上下文”的模块接入方向，尽量不让普通模块感知电脑地址。内部仍需处理请求身份、截止时间、执行实例和错误，不能因为实例唯一就忽略网络失败。

具体边界：

- 本机模块直接执行；远端不可达时明确失败，不在本机启动替代实例。
- 执行与安静执行保留现行区别，确认、进度、脱敏和日志规则继续有效。
- 远端超时可能表示已经执行但回执丢失，应表达“结果未知”；写操作不自动重放。
- 节点身份由连接认证确认，不能把自报 `source` 或套上模块来源章当作可信授权；跨节点安装须有明确动作批准。
- 远端结果只能传可序列化的数据。现行同进程允许的 CLR 活对象、委托、UI 对象和本机文件路径不能透明搬到另一电脑。
- 事件须防止双向转发绕圈，保证约定范围内的顺序；重连能补状态快照，但是否补发历史事件待定。

## 七、每台电脑一个前端

### V8-DES-009 前端按节点定位

普通模块保持逻辑宿主内唯一；前端登记调整为每物理节点唯一。前端资格通过通用角色契约声明与核对，不由宿主具体模块名白名单决定。

业务模块的命令全局按模块身份路由，前端窗口、布局和界面生命周期操作按节点或发起会话定位。两台电脑上的同名前端命令不能互相覆盖或成为模糊的全局目标。

跨节点调用的确认回到发起操作的界面；目标端需要 UI 线程的操作仍在目标节点的前端线程执行。确认通道缺失或失联时保留拒绝闸口。

前端包也可以同步到所有节点，但首期每节点前端的自动升级范围仍需确认，不把普通模块的“单目标装载”机械套到前端上。

## 八、断网、重连与手动接管

### V8-DES-010 离线不改变归属

节点掉线后保留模块归属，只把可达性标为离线。另一节点即使已经缓存了包，也不会自动装载。已运行的本机模块可以继续工作，涉及远端模块的调用失败。

节点启动或重连时，先核对包、归属与实例状态，再对外发布有效的全局命令目录。旧包或旧运行记录不能覆盖更新后的装载决定。

### V8-DES-011 正常迁移与离线接管

正常迁移：原节点停止模块并确认 → 按模块数据策略处理数据 → 更新归属 → 新节点装载并核对。只同步 nupkg 不等于迁移了运行数据。

原节点不可达时，允许用户明确发起离线接管的讨论方案为：新节点记录接管决定并运行；旧节点重连后识别该决定、撤下旧实例，保留本地包与数据。该策略及确认方式须在实施前拍板。

**在线状态本身不授予装载权；重连时依据明确的归属变更，不简单规定“在线的一台总是赢”。**

示例：

| 时点 | A | B | 处理 |
| --- | --- | --- | --- |
| 初始 | 模块归属 A，正在运行 | 只有缓存包 | B 不装载 |
| A 断网 | 可能继续运行 | 看到 A 不可达 | 不自动接管 |
| 人明确在 B 接管 | 不知道 B 的新决定 | 记录接管并运行 | 报告暂时可能双实例 |
| A 重连 | 发现更新后的归属为 B | 保持运行 | A 撤下实例，停止发布旧目录 |

离线接管无法保证分区期间物理上绝对只有一个实例。若最终要求任何时刻严格唯一，必须拒绝失联节点的接管，或另行采用能让旧实例停止有效执行的所有权机制；不能只凭重连后退让宣称全程唯一。

### V8-DES-012 冲突识别

包内容冲突、装载归属冲突和模块数据冲突分别处理：

- 包依据制品哈希和发布记录同步，旧节点不自行覆盖当前发布索引。
- 归属记录应有可追踪的变更身份和前后关系；明确继承的接管可使旧记录退让，不能用机器时钟或文件时间裁决。
- 两边各自在断网期间修改归属，形成并发分支时，应显示冲突并由人选定归属，不任意选一个节点继续作为全局有效实例。
- 两边运行产生的数据分别保留并报告冲突。宿主不通用合并业务数据，也不自动用在线节点数据覆盖离线节点。

归属记录的持久化位置、修订机制，以及启动时无法查询对方或云端时的精确规则，列为待定事项。首期保留已知本机归属的离线运行，会接受离线接管导致的暂时双实例风险。

## 九、数据、依赖与兼容性

### V8-DES-013 包同步与数据迁移分开验收

`ModuleData` 是模块可写状态，`ModuleContent` 是只读随包内容。各节点缓存包不自动同步 `ModuleData`。迁移需要模块声明并提供适合自己的导出、复制或共享存储方案；无法安全迁移的数据应阻止普通迁移或由用户明确选择处理方式。

远端返回的路径属于执行节点；需要读取文件时通过明确的内容获取能力处理，不能把它当作调用节点本机路径打开。

### V8-DES-014 接入契约升级评估

现行 `dependsOn` 约束本机接入次序。V8.0 要区分远端服务就绪与本机程序集依赖，不能用“另一节点有模块”满足本机加载所需依赖。模块整体就绪和节点就绪也需要分别表达。

节点信息、全局目录、远端错误、归属、前端作用域与事件语义可能影响公开载荷或接口。是否保持现行 Core 二进制兼容，要在源码设计阶段验证，本书不预先宣称公开 API 零变化。

实施 V8.0 时同步 AGENTS、manifest、版本源、现行合同、接入白名单与 PublicAPI 声明。当前 AGENTS 已统一为源码 7.0.0、开发线 7.x，固定冻结基线已退役；V8.0 仍处于方案与环境准备阶段。

## 十、实施顺序与验收场景

下列是首期验收场景；实现与隔离测试已在本仓完成，双机实验另有运行记录。

| 阶段 | 交付内容 | 最小验收场景 |
| --- | --- | --- |
| 1 | 包索引、云上预装载区、节点缓存 | 完整包校验；同版本不同内容识别；失败不暴露半包；缓存变化不触发装载 |
| 2 | 两节点认证直连、目录与指令路由 | A 调 B 并取回结果；双向调用；非法节点拒绝；断线不重放写操作 |
| 3 | 普通模块归属与每节点前端 | 同步包只启动指定实例；各自前端独立；跨节点确认与 UI 线程目标正确 |
| 4 | submit/finish 的目标交付 | 本机、远端、预装载区三个目标；审核复用同一哈希与目标；离线目标明确失败 |
| 5 | 重连补同步、迁移与接管 | A 断网、B 手动接管、A 重连退让；并发归属冲突可见；业务数据无自动覆盖 |

宿主门禁只验证本仓。跨节点协议可以用本仓测试节点或替身验证；真实两机联调需要单独记录节点状态、包哈希、实例与回执。模块自身的数据迁移和远程适配由各模块仓按开发手册处理，不引入跨仓 ProjectReference。
