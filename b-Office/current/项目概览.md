# HistoryVulcan 项目概览

更新日期：2026-09-07。源码 **5.3.0**；冻结基线 **5.1.2 / v5.1.2**。本目录是独立 Git 仓库，邻接编号项目不属于本仓。

## 职责

| 组件 | 当前职责 |
| --- | --- |
| Core | 模块入口与上下文、命令注册和执行、日志与存储合同 |
| Services | 模块包校验、发现、装载、卸载和事务；设置、日志、目录 DTO；开发和发布引擎 |
| ServiceHost | 宿主组合、运行循环、确认路由、本地 CLI 与当前用户 runtime 管道 |
| App / Cli | WinExe 与同目录 Console CLI 入口 |
| DemoModule | 本仓起步示例；对齐现行模块接入面，不进正式运行区 |
| HistoryAurora | 桌面界面、布局和确认交互；独立模块 |
| HistoryMercury | 命令工作台与快捷键；独立模块 |
| HistoryPortunus | Web/MCP 协议、监听、鉴权和会话；独立模块 |

宿主维护通用注册与生命周期，不提供模块领域抽象，不包含 HTTP/WebSocket/MCP 网关。WPF 模块需要的程序集解析、UI 线程编组和卸载仍保留。

## 运行与恢复

宿主发现固定运行区直属完整 manifest 包，不读取项目库、发布归档或裸 DLL。包内不可变文件受完整 SHA256SUMS 约束，`data/` 为模块可变数据，不参与载荷校验。无模块可以启动；坏包隔离并留下诊断。

整轮装载按 `dependsOn` 排序逐个接入，成功一个发布一个；失败模块命令全部不可执行。整轮处理结束后提供就绪状态并发送已声明的 `<域>.host.ready`。就绪表示本轮结束，失败详情仍需查模块列表。单包热装不发送整轮通知。

在线/离线安装和移除共用事务阶段。备份前失败保留原目标；新包接入前复制旧数据，提交成功后才清理旧包。恢复失败保留备份并返回路径，清理失败不撤销已提交结果。

`vulcan.app.get/set` 是通用设置入口；原存储位置与参数不变。旧键由所属模块解释，宿主不自动迁移或删除。敏感值在命令回显、结果、异常与进度中脱敏；内部 `InvokeAsync` 保持原始载荷语义。

## CLI 与发布边界

`--cli` 固定使用离线组合；`--runtime` 连接活宿主，不可达时不降级。runtime 仅接受模块 list/ready/reload/install，reload/install 要求显式批准和有效握手。

模块开发走同目录 Console CLI 的 `vulcan.dev.start/submit/finish`。宿主禁止走这三条，使用进程内 `vulcan.release.cycle`。发布拒绝替换正在运行的自身目录；正式发布、提交和部署另行授权，CI 只做还原、构建、测试、格式和 API 门禁。

## 5.3.0 兼容变化

本版按用户指定版本删除旧发现、源确认、选择性命令注册、MCP 配置迁移与远程确认接口，保留冻结标签。精确删除记录在 Unshipped，消费摘要见[模块 API](../package/模块API.md)，偏离主版本规则的批准范围见[DEC-060](有效决策.md)。

`FrontendExecutor`、`RemoteExecutor`、`ShouldUseRemoteCommand` 及现用模块管理、目录 DTO、设置与路径合同有已部署消费方，继续保留。这不赋予宿主网关所有权。

验收与未执行的部署/真机项目见[验证合同](验证合同.md)。旧版本演进记录见[清理前合同归档](../history/5.2.1-现行合同归档.md)。
