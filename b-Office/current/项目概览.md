# HistoryVulcan 项目概览

源码：**6.0.0**；冻结基线：**v6.0.0**。本仓是独立 Git 项目。

| 组件 | 职责 |
| --- | --- |
| Core | 统一模块契约：模块入口、`IModuleContext`（窄总线 `ICommandBus`、登记口 `ICommandRegistrar`、只写日志、运行环境、事件订阅、唯一前端登记）与描述符/结果类型；公开面即[模块开发手册](模块开发手册.md)「接入契约」白名单 |
| Services | 总线与注册表实现、完整包发现、装卸与事务、设置/日志、开发和发布引擎；程序集没有公开类型 |
| ServiceHost | 组合根、运行循环、缺省确认、离线 CLI 与当前用户 runtime 管道；程序集没有公开类型 |
| App / Cli | WinExe 与同目录 Console CLI 入口 |
| HistoryAurora | 桌面界面、布局和确认交互；独立模块，经 RegisterFrontend 登记为宿主唯一前端 |
| HistoryMercury | 命令工作台与快捷键；独立模块 |
| HistoryPortunus | Web/MCP 协议、监听、鉴权和会话；独立模块 |

宿主维护通用生命周期与命令集成，不提供模块领域抽象。WPF 解析、线程编组和可回收装载仍属宿主职责；界面线程、确认交互与界面生命周期中继由唯一登记的前端提供，宿主总线在交给模块前封口。

运行主线：固定 Modules 完整包 → 校验与发现 → 按 dependsOn 接入并发布成功模块的命令 → 整轮就绪通知。安装/移除使用事务保护旧包（模块数据在槽位之外的 `ModuleData\<模块名>`，不随装包变动）；失败语义见[技术合同](技术合同.md)。

`--cli` 在离线组合执行，`--runtime` 连接活宿主。模块开发流程见[开发手册](模块开发手册.md)，宿主发布及真机检查见[验证合同](验证合同.md)。

6.0.0 按 DEC-071 收口统一模块契约：模块只见窄接口，宿主指令的 Data 只交写明的 JSON 形状，模块调用由宿主盖来源章，宿主源码不认识任何模块。各版本的演进与依据见[有效决策](有效决策.md)，接入契约见[模块开发手册](模块开发手册.md)，内部文件定位见[源码导航](../../b-Code-HistoryVulcan/README.md)。
