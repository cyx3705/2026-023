## 目录与资产边界

### 根目录规则

以下路径均相对于仓库根。活动目录必须用 a/b/z 前缀；实际活动、生成、归档和正式发布根以
`project.manifest.json` 为机器真值。

根上只保留**工具链必须向上查找、或合同硬编码仓库根**的文件，不要再往根上摊独立 JSON / 配置副本：

| 文件 | 为什么在根 |
| --- | --- |
| `project.manifest.json` | AI-ready 合同入口；`Test-ProjectContract.ps1` 只认仓库根这份 |
| `global.json` | CI `global-json-file` 与 `dotnet` SDK 解析都沿目录向上找，必须是解决方案的祖先 |
| `nuget.config` | NuGet 同样向上查找；这一份覆盖源码和测试。`b-Code-HistoryVulcan/` 内不再放副本 |
| `HistoryVulcan.sln` | 唯一解决方案；CI、候选构建、格式门禁都用它 |
| `Directory.Build.props` | MSBuild 向上导入，让测试工程继承同一套 Nullable / 警告即错误 |
| `AGENTS.md`、`README.md`、`.ignore` | 人/AI 入口；`.ignore` 是合同必需文件 |
| `.gitignore`、`.gitattributes` | Git 只认仓库根 |

`Directory.Build.user.props` 由 `vulcan.worktree.create` 生成，指向本机正式快照，**不入库**。
不要把 `global.json` / `project.manifest.json` 挪进 `b-*`：它们不是祖先目录，SDK 和合同脚本都找不到。

活动项目目录：

| 路径 | 级别 | 职责 | 编辑规则 |
| --- | --- | --- | --- |
| `b-Code-HistoryVulcan/` | b | 框架源码 | 主要实现权威源 |
| `b-Code-Eng/` | b | 候选构建、门禁与发布管线 | 不放产品源码 |
| `b-Code-Tests/` | b | HistoryVulcan 自动化测试 | 独立测试工程与锁定依赖 |
| `b-Office/` | b | 现行合同、消费文档源和历史边界 | 按 current/package/history 分流 |
| `z-Publish/` | b | 当前候选、虚拟验证和最小正式历史副本 | current/virtual 可重建，history 不可手改 |
| `z-Publish/` | z | 跨项目当前正式消费快照 | 只由发布流程整体更新 |

`.github/`、`.git/`、`.vs/` 等点号目录属于工具基础设施，不是项目级内容。根 `eng/`、`Unused/` 和
本地 `artifacts/` 是 manifest 明确排除的既有非活动目录；默认不读取、不迁移，也不得作为新实现入口。
新增活动目录必须使用 a/b/z 前缀并同步更新 manifest 与现行合同。

### b 级目录职责

- `b-Code-HistoryVulcan/`：Core、Services、ServiceHost、Extensibility 与独立可执行宿主。桌面 Shell 在 HistoryAurora。
- `b-Code-Eng/`：候选构建、API 基线、质量门禁和项目合同等维护脚本。
- `b-Code-Tests/HistoryVulcan.Tests/`：公开合同、安全、模块与命令回归；不继承产品包发布元数据。
- `current/`：项目概览、技术合同、有效决策、验证合同、冻结合同、断头指令审计。
- `package/`：随版本发布的消费合同编辑源和稳定复用入口。
- `history/`：已结束版本、已替代方案、审查与阶段施工记录，默认不进入维护上下文。
- `b-Code-Eng/release/`：发布文档清单（`consumer-docs.json`）与可选 Inno 安装脚本。
- `z-Publish/`：唯一一份可覆盖候选和完整发布测试结果。
- `z-Publish/history/<版本>/`：正式发布后生成的 Z 级最小历史副本，不可覆盖或手改。
- `z-Publish/virtual/`：从 history 临时重建的历史链路验证快照，不入库。

### z 级消费快照

- Z 级是稳定元地址，不是源码副本或历史版本集合。
- 根 `manifest.json` 声明当前版本和文档清单；`host/` 保存可运行宿主，`docs/` 保存同版本消费合同。
- 消费方和 AI 先读取根 manifest，再按清单读取 `docs/`，不扫描历史区或源码反推用法。
- 正式更新必须由发布脚本整体替换，并校验 manifest、文件清单和 SHA-256。

### 文档生命周期

1. 仍会约束后续工作的规则进入 `current/`；同类规则优先合并，不按问题或版本无限新增元文件。
2. 面向消费方的稳定 API、命令、接入和限制进入 `package/`。
3. 已完成方案、审查清单、整改过程和版本证据进入 `history/`。
4. `b-Code-Eng/release/` 只保存生成规则，不保存手工发布副本。
5. 合并或归档前先把仍有效内容提炼到 current；历史原文不得覆盖 current、源码或测试事实。
