# 5.7.0 模块开发管线易用性升级说明

- 状态：**已在 5.7.0 实施**（REQ-HOST-072…076、DEC-067）。U6 的 `help` 参数未做，理由见 DEC-067；本文保留为意见稿原文
- 日期：2026-09-21
- 来源：HistoryMinerva 4.12.0 一轮完整走 `vulcan.dev.start → submit → finish` 的实际使用（宿主 5.6.1）
- 范围：`vulcan.dev.start / submit / finish` 三条指令的参数、回执与护栏。**不改**管线阶段、候选规则、
  发布登记表、MCP 隐藏策略，也不动 `vulcan.release.cycle` 在主树上的行为。

## 总体判断

主流程一次走通：三步分工清楚，dryRun 预检有用，submit 一条完成门禁/候选/提交/热装，finish 复核候选后快进合并、
回收工作区也没有意外。问题集中在三处：**必填参数多且可推导**、**回执不能证明模块真的接上**、**回执噪声与格式瑕疵**。
另有两条护栏只能靠使用者的历史经验才知道。

| 编号 | 改动 | 优先级 | 兼容性 |
| --- | --- | --- | --- |
| U1 | submit / finish 只需 `worktree=` | 高 | 旧参数照收 |
| U2 | 工作区内的未提交改动不再要求 `allowDirty` | 高 | 旧参数照收（变为无操作） |
| U3 | 热装回执带模块附着状态，未接上即失败 | 高 | 回执 Data 追加字段 |
| U4 | 迁根提示按 agent 显示；修回执格式与 dryRun 措辞 | 中 | 仅文本 |
| U5 | 主树有未提交改动时 start / submit 给出警告 | 中 | 仅文本 |
| U6 | 三条指令接受 `help`，start 回执给出可直接复制的 submit 命令 | 低 | 新增 |

## U1 submit / finish 只需 `worktree=`

**现状**

- `vulcan.dev.submit` 必填 `name`、`msg`、`worktree`（`DevPipelineCommands.cs` 第 72–89 行），
  `vulcan.dev.finish` 同样三个必填（第 99–113 行）。
- start 回执只写「改完后调用 vulcan.dev.submit」（第 150–152 行），不提必填项，首次调用必然缺参失败。
- `name` 可由工作区推出：工作区位于 `<工作区根>/<项目目录>/<工作区名>`，`ReleaseCommands.TryResolveModuleByProject`
  已能从项目目录反查登记表。
- **finish 的 `msg` 完全没被使用**：`FinishAsync` 收下后既不传给 `WorktreeCommands.MergeAsync`，也不写进任何提交
  （合并是快进）。

**改动**

1. submit / finish 的 `name` 改为可选：省略时由工作区所在项目目录经 `TryResolveModuleByProject` 推出；
   显式传入且与推出值不一致时 `Fail`，说明两者各是什么。
2. submit 的 `msg` 改为可选：省略时取工作区名里的 slug（`<基点>-<序号>-<agent>-<slug>` 的最后一段）。
3. finish 的 `msg` 删除语义：仍接受以免旧调用失败，传了就在回执里提示「finish 不产生提交，msg 已忽略」。
4. `worktree` 保持必填，并继续接受目录名或绝对路径。

**验收**

- `vulcan.dev.submit worktree=<名>` 与 `vulcan.dev.finish worktree=<名>` 在登记模块上成功；
- `name=` 与工作区项目不符时失败并点出两个值；
- 旧写法 `name= msg= worktree=` 行为不变；
- 测试放 `ReleasePipelineTests`（推导、冲突、旧写法三例）。

## U2 工作区内的未提交改动不再要求 `allowDirty`

**现状**

`ReleaseCommands.CycleAsync` 在工作树有改动时要求 `allowDirty=true`，否则以退出码 2 拒绝（第 334–341 行）。
这道门对**主树**上的 `vulcan.release.cycle` 有意义；对 dev 工作区，「改了文件、还没提交」恰恰是 submit
要处理的正常状态（submit 自己负责提交），于是每次 submit 都得传这个参数。

**改动**

- 经 `vulcan.dev.submit` 进入且目标是工作区时，跳过这道门；回执与 Data 仍列出将被提交的文件（`DirtyFiles`）。
- 主树上的 `vulcan.release.cycle` 保持原样。
- `allowDirty` 参数在 dev.submit 上保留为无操作，避免旧调用失败。

**验收**：工作区有改动、不传 `allowDirty` 时 submit 与 dryRun 均成功并列出文件；主树 `release.cycle` 仍在脏树时以退出码 2 拒绝。

## U3 热装回执带模块附着状态

**现状**

`ModulePackageHotReload.InstallCurrentAsync` 只转述 `vulcan.module.install` 的结果（第 52–55 行），
回执「已热重载到活宿主」只证明包装进去了。曾出现回执成功、模块却 `attached=false` 的情况（PendingAttach 重复，
见 5.2.0 前后的记录），使用者因此每次都要另外用 `diana.host.modules` 核对。

**改动**

- 装完后对同一模块查一次活宿主模块表，回执与 Data 追加：`version`、`attached`、`commandCount`、`attachFailures`。
- `attached=false`、版本与候选不符、或 `attachFailures` 非空时，submit / finish 返回 **Fail**，
  文案给出失败原因首条，并指向宿主日志 `%AppData%\HistoryVulcan\service\logs\shell-<日期>.log` 的 `[module.discovery]`。
- 候选已提交这一事实照旧写明（不回滚），只是结论不再是成功。

**验收**：模拟附着失败的测试宿主上 submit 返回 Fail 且 Data 带 `attachFailures`；正常路径 Data 中 `attached=true`、版本等于候选版本。

## U4 回执噪声与格式

**现状**

1. 迁根提示（`MoveRootHint`、`MoveRootBeforeFinish`，第 30–33 行）以及 CycleAsync 末尾同义的一段，
   在 start、submit、finish 每次都整段输出，只对 Cursor/grok 有用。
2. dryRun 回执：
   - 文件清单首行缺前导空格——`ToolProcess.Capture` 对整段输出 `Trim()`（第 36 行），
     吃掉了 `git status --porcelain` 首行的状态列空格，于是首行是 `M b-…`、其余是 ` M b-…`；
   - 清单最后一行与下一句粘连成 `…project.manifest.json不会写日志…`（`ReleaseCommands.cs` 第 359–360 行缺换行）。
3. `SubmitAsync` 无论是否 dryRun 都追加「已注册到宿主审核」（`DevPipelineCommands.cs` 第 175 行），
   dryRun 时读起来像真的登记了。

**改动**

1. 迁根提示只在 agent 为 `cursor` / `grok` 时输出；agent 取自工作区名（start 已把它写进名字）。
2. dirty 状态改用不裁剪首行的读取（只裁尾部换行），清单与后文之间补换行。
3. dryRun 回执不再追加「已注册到宿主审核」，改为「dryRun 未登记审核」。

**验收**：文本快照测试覆盖 dryRun 回执（首行格式、换行、措辞）；agent=claude 的工作区回执不含「迁根」。

## U5 主树改动护栏

**现状**：直接在模块主树改代码时，管线不会提示；等到 finish 才发现改动不在工作区里、无法并回，
只能手工导补丁搬进工作区。

**改动**

- `vulcan.dev.start`：项目主树有未提交改动（排除 `z-Publish`）时回执加一行警告，列出文件数与前 5 个路径，
  说明「这些改动不会进入新工作区」。不拒绝开工作区。
- `vulcan.dev.submit`：同样检查主树，有改动时警告「主树有 N 个未提交文件，不在本次提交内」。

**验收**：主树造一个改动后 start / submit 回执含警告；主树干净时不出现。

## U6 可发现性

- start 回执末尾给出一条填好工作区名、可直接复制的 submit 命令，例如
  `HistoryVulcan.Cli.exe --cli "vulcan.dev.submit worktree=<名>"`（依赖 U1）。
- 三条指令接受 `help` 参数（或 `--cli "vulcan.dev.submit help"`），输出与
  `vulcan.command.show name=…` 相同的用法，省去先知道 `command.show` 这一步。

## 不在本版范围

- 回执「文字 + 整行 JSON」的重复：属于 CLI 通用输出格式，若要改应单列（例如 `--json` 只出 Data），不在管线里特判。
- 模块自己的质量门要在 submit 后才能转绿（候选由 submit 生成、工作区里需显式传宿主包根）：属于各模块脚本，
  由模块侧处理。
- 开发管线继续对 MCP 隐藏。
