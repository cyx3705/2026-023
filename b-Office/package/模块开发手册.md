# 模块开发手册

面向为 HistoryVulcan 开发**模块**的人和 AI。接口事实以 [模块 API](HistoryVulcan_模块API.md) 为准；本文件只写流程。

起步抄宿主仓 `b-Code-Samples/DemoModule`：现行合同是 `IModuleContextAware` + `RegisterCommands` + 完整运行包，不是拷 DLL、不是旧 `.panel.json`。

## 五条硬规则

1. **只有 `agent=grok` 迁根。** 其他 AI 留在当前对话根，按 `start` 返回的绝对路径改 F 盘。不要用 Handoff 或打开文件夹代替。
2. **三条命令只给模块，只走同目录 Console CLI。** `HistoryVulcan.Cli.exe --cli vulcan.dev.start|submit|finish`。不要走 MCP，不要直接调 `vulcan.worktree.*` / `vulcan.release.*`。宿主禁止走这三条。
3. **`finish` 会删工作区。** grok 必须先迁到该模块 Clio 主树 `main`，等到迁根成功回执，再跑文内 A–D 并把输出留在本轮对话。其他 AI 不迁根，但可见路径不能是正在删除的那条工作区。未确认就 `finish`：这一轮对话作废，不要再迁根补救。
4. **不许停宿主。** 不要 `vulcan.svc.stop` / `restart`、`vulcan.app.quit`，不要杀 `HistoryVulcan.exe`。那些要人工确认，会把对话卡住。热重载不关宿主。
5. **第一轮在 `submit` 成功后停。** 没有人的审批，禁止 `finish`。

`msg=` 不要含空格。正式 CLI 在 `z-Publish\host\HistoryVulcan.Cli.exe`，须与正在运行的 `HistoryVulcan.exe` 同目录。

## 日用三步

```
人发起 → start 开 F 盘工作区 →（仅 grok）迁进工作区
        → 只在该工作区改 → submit（门禁、写 z、热重载）
        → 第一轮停，等人审批
        → 通过后 grok 迁回 Clio 主树 main，跑 A–D → finish
```

| 步 | 命令 | 做什么 |
|---|---|---|
| 1 | `--cli vulcan.dev.start project=<YYYY-NNN-模块> slug=<问题> agent=<ai>` | 开分支和工作区 |
| 2 | `--cli vulcan.dev.submit name=<模块> msg=<说明> worktree=<工作区>` | 门禁、写该工作区 z、提交、只热重载这一模块 |
| 3 | `--cli vulcan.dev.finish name=<模块> msg=<说明> worktree=<工作区>` | 审批通过后：并回 main、删工作区、注册运行包 |

查参数：`--cli vulcan.cli.show name=vulcan.dev.submit`。并行再开工作区才传 `confirm=true`。脏树传 `allowDirty=true`。`dryRun=true` 只报告计划。

工作区根默认 `F:\ai工作区\<项目>\<短SHA>-<序号>-<标识>`，分支 `ai/<项目>/<同名>`。序号自动跳过已有目录和旧分支；同一 slug 再 start 得到 `-2-`，不要删旧分支。人不要把 F 盘工作区加成 Cursor 主项目。

日用只碰这三条，再加上核对用的 `--runtime vulcan.module.list`。不要单独 `vulcan.module.install` / `reload`，不要 `vulcan.release.cycle`。

## 开工作区

```
HistoryVulcan.Cli.exe --cli vulcan.dev.start project=2026-021-HistoryMercury slug=explorer-notify agent=claude
```

会生成不入库的 `Directory.Build.user.props`，把 `HistoryVulcanPackageRoot` 指回宿主快照。不要改隐藏的 `worktree.root`。不要在模块 Clio 主树上改。

### 仅 grok：搬进工作区

迁根工具会去抢 `main`，而主树已经占着它，直接迁会报 `main is already used by worktree`。按这个顺序让开，不要跳过迁根，也不要把工作区先切到 `main`：

```
git -C C:\OneHistory\HistoryClio\<模块主树> checkout --detach
# move_agent_to_root → F:\ai工作区\<项目>\<工作区名>
git -C F:\ai工作区\<项目>\<工作区名> checkout ai/<项目>/<工作区名>
git -C C:\OneHistory\HistoryClio\<模块主树> checkout main
```

任何一步失败先把主树 `checkout main`。迁根后若目标仓出现源工作区的 `ai/...` 分支：立刻 `checkout main` 并删掉误建分支。

## 改代码

模块依赖已发布的 `z-Publish/host/HistoryVulcan.*.dll`（`<Private>false</Private>`），不要自动改去引用宿主源码工程。联调才显式传 `-p:HistoryVulcanSourceAvailable=true`。

抄 `b-Code-Samples/DemoModule`。真正模块把其中的 `ProjectReference` 换成对宿主快照的 `HintPath`。不要实现已删除的 `IUiModule` / `IShellUi*`。`Attach` 里不要跨模块调用；整轮装载完成后再干的活，登记 `<域>.host.ready`。

窗格用命令上的 `ui.*` 注解（键由 Aurora 定义）。未装界面模块时 `vulcan.ui.*` 是未知指令。

新模块要走管线，须在宿主仓 `b-Code-Eng/pipeline/module-publish.manifest.json` 登记 `kind=module`。促级前三处身份必须一致，否则拒绝：csproj / Version.props、源 `module.manifest.json`、管线写入的快照清单。

跨仓路径不要写成可点击的相对 Markdown 链接（F 盘工作区不是 Clio 兄弟目录）。

## submit

```
HistoryVulcan.Cli.exe --cli vulcan.dev.submit name=HistoryMercury msg=说明 worktree=<start返回的绝对路径或目录名>
```

`worktree=` 必填。省略会走到主树正式促级。成功回执必须含「已热重载到活宿主」；活宿主不可达则失败，不降级。同版本再 submit 覆盖该工作区当前候选。

核对：

```
HistoryVulcan.Cli.exe --runtime vulcan.module.list --format json
```

看 `data` 或 `runtimeAck.modules`：该模块 `instanceId` 已变（版本可以不变），Aurora 的 `commandCount` 不得为 0。不要只看 `moduleInstanceIds`。

不要 `--runtime vulcan.module.reload`（会拆掉全部模块）。门禁未过就改代码再 submit，不要改门禁期望值，除非期望已经过时。

## finish

**先读本节禁止，再跑 A–D。没有把检查输出留在本轮对话里，禁止 finish。**

`finish` 删除 `F:\ai工作区\<项目>\<工作区>`。对话根还在该目录、或 git 已半删，再调用：Cursor 占路径删不掉，之后迁根报 `not a git repository`。这一轮作废。人关对话，新开对话打开该模块 Clio 主树 `main`。

工作区 = `F:\ai工作区\<项目>\<工作区名>`；主树 = `C:\OneHistory\HistoryClio\<该模块主树>`。

```
# A. 可见工作区路径
#    grok：必须等于主树。仍含 F:\ai工作区 = 没迁走。
#    其他 AI：必须不是正在 finish 的那条工作区绝对路径。
#             另一条 F 盘残留、或 Vulcan / 其他模块主树 = 通过。

git -C "<工作区>" rev-parse --is-inside-work-tree          # 必须 true
git -C "<主树>" worktree list                              # 必须仍有那条 F 盘路径
git -C "<工作区>" status --porcelain                       # 必须空；有输出先 submit
git -C "<工作区>" branch --show-current                    # 必须 ai/<项目>/<工作区名>
git -C "<主树>" branch --show-current                      # 必须 main
```

```
HistoryVulcan.Cli.exe --cli vulcan.dev.finish name=HistoryMercury msg=说明 worktree=<工作区目录名>
```

闲置且与 main 齐平的工作区也用 `finish` 回收。分支一律保留。Diana 不 push、不建 PR。候选热重载失败不回滚已成功的提交。

## 模块文档分工

一个模块的对外面是**三个消费面**，各写各的地方。混在一起写，等于三个都没写。

| 面 | 消费者 | 消费方式 | 写在哪 |
|---|---|---|---|
| 代码面 | 别的模块的 C# 代码 | 引用本模块 `*.Contracts.dll`，在自己进程里调纯函数 | **本模块技术合同** `b-Office/current/技术合同.md` |
| 总线面 | 别的模块的 C# 代码 | `context.Bus.ExecuteAsync("<域>.…")` | **模块 API** `b-Office/package/模块API.md` |
| AI 面 | AI | MCP 工具 | **不单独写**：MCP 服务按 `Readonly && !Hidden` 自动投影，工具描述就是它的 API |

### 模块API.md 只写总线面

**它是跨模块代码调用的合同，不是本模块的全部说明书。** 不要把 Contracts 里的类型清单搬进来——那是自家实现细节的公开投影，属于技术合同；模块 API 只回答「别的模块在总线上能让我干什么」。

逐条命令写满这五格，缺一格就是没写：

1. **能做什么**——一个具体动作，不是一个功能领域。
2. **谁会用、什么时候用**——写不出消费者，这条就不该在这份文档里。
3. **怎么调**——命令名、每个参数、必填还是可选、缺省值。
4. **拿回什么**——`CommandResult.Data` 的**确切类型**（哪个程序集的哪个 record），没有 Data 就明写「无」。
5. **失败与边界**——什么时候 `Fail`，什么时候 `Success` 但没干活，占不占 UI 线程，有没有状态、能不能并发。

再加两条硬要求：

- **优先给无状态入口。** 绑页面当前选择的命令没有并发、没有幂等、调用方得先按频道再按播放。跨模块消费要的是「对这个路径做这件事」。
- **末尾必须有缺口台账。** 今天拿不到什么、为什么、建议怎么补，逐条列。遮住缺口，消费方只会自己抄一份逻辑——那时候单体应用比同宿主多模块耦合更低。

### 技术合同写代码面

`*.Contracts.dll` 里每个公开类型、纯函数、常量：签名、语义边界、为什么是这条规则不是那条。**同一件事只允许一个判据**，写清楚它在哪，别的模块和本模块都引它，不许各写一份。

### AI 面不写文档，写描述

想让 AI 用得上，靠的是命令注册时的 `Summary`、`Parameters` 描述和 `Example` 写得像给 AI 看的，以及**该只读的别标写入、该露出的别挂 `HiddenReason`**。一条命令 AI 用不了，几乎总是这两处的问题，不是缺文档。

样板见 `diana.docs.read domain=minerva file=docs/模块API.md`（HistoryMinerva 4.10.2）。各模块按本节逐个对齐，对齐时把搬错位置的内容移到该去的文件，不是复制一份。

## 文档与看界面

跨项目读已发布文档：先 `diana.docs.catalog`，再按返回的 `diana.docs.read domain=<通道> file=... heading=...`。手册超过 12 KiB 必须带 `heading`。`diana.docs.*` 不是开发管线，不要传给 `--cli` / `--runtime`。

只有 **Diana MCP 工具未暴露或调用失败**时，才记录原因后降级读目标项目正式 `z-Publish/docs`。不要打开邻接项目的 `b-Office/current`、`package` 或 worktree。

只读观察桌面：`diana.view.windows` → `diana.view.capture handle=<句柄>` → **实际读取**返回的 PNG，并留下尺寸、捕获方式和 SHA。Diana 后台捕获不移动鼠标、不切换前台。禁止为只读观察调用 Computer Use、点击窗口、移动鼠标或抢占前台。View 失败先记录原因；确需点击、输入、拖拽时先取得用户同意。

## 卡住时

| 现象 | 先看什么 |
|---|---|
| submit/finish 一直不返回 | 宿主日志末尾。不要停宿主 |
| 调了 stop/restart/quit 不返回 | 在等人工确认。取消调用 |
| 工作区删不掉 | 多半是 Cursor 窗口占路径，不是宿主 |
| Aurora 指令变成 0 | 误用了整仓 reload。当前 install 只装一个模块 |
| 门禁版本对不上 | 三处身份没对齐 |
| json 里没有模块名 | 看 `data` / `runtimeAck.modules` |
| 切根报 main 已被 worktree 占用 | 仅 grok，按开工作区四步 |
| finish 后迁根报 not a git repository | 对话已废。不要再迁根 |
| 对宿主调 start | 对。宿主禁止走开发管线 |
| 文档通道把整本手册灌进对话 | 加 `heading=` |
