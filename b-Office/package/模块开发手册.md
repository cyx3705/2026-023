# 模块开发手册

面向为 HistoryVulcan 开发**模块**的人和 AI。

## 迁根适用范围：只有 grok 迁根

**是否迁根只看 `vulcan.dev.start` 的 `agent=`：只有 `agent=grok` 执行迁根。**

- **grok：** 必须使用 Cursor 的 `move_agent_to_root`，按本手册完成迁入 F 盘工作区和 `finish` 前迁回模块 Clio 主树。
- **其他 AI（包括 Codex、Claude）：** 一律不迁对话根，不执行 `move_agent_to_root`，也不得用 Handoff、切换项目、打开工作区或产品里的任何同类能力代替。对话始终留在当前根，通过 `vulcan.dev.start` 返回的绝对路径读写 F 盘工作区。
- 其他 AI 看不到 `move_agent_to_root` 是正常产品边界，不是工具缺失、权限故障或流程失败，也不得因此停止模块开发流程。

本手册后文凡写「迁根」「切根」「搬进工作区」或 `move_agent_to_root`，**均只适用于 grok**；除非段落明确写「其他 AI」，否则其他 AI 不执行。

## 禁止：对话根还在**正在 `finish` 的那条**工作区就调用

**这是死命令，不是提醒。违反一次，这一整轮 Cursor 对话作废。**

`vulcan.dev.finish` **会删除** `F:\ai工作区\<项目>\<工作区>`。Cursor 的 `move_agent_to_root` **永远先在当前对话根**执行 `git checkout --detach`。因此：

| 你做了什么 | 立刻发生什么 |
|---|---|
| 对话根仍是**正在 `finish` 的那条** `F:\ai工作区\<项目>\<工作区>` | Cursor 占着路径 → 删目录 Permission denied，或 git 已卸登记、文件夹还在 |
| `finish` 已经把目录删了，对话还钉在那条路径上 | 之后每一次 `move_agent_to_root` 都在已死目录里跑 git，报 `fatal: not a git repository` / `Cannot migrate: failed to detach worktree HEAD` |
| 这时再试迁根、再 `finish`、再对那条路径跑 git | **救不回来。** 这一轮对话废了。人只能关掉它，新开对话，打开该模块 Clio 主树 |

**grok 调用 `finish` 之前必须全部为真，缺一条就禁止调：**

1. 已经 `move_agent_to_root` 到 `C:\OneHistory\HistoryClio\<该模块主树>`，**不是** HistoryVulcan 宿主仓，**不是**别的模块。
2. 系统回了 `Moved agent root to C:\OneHistory\HistoryClio\<该模块主树>`。只发了工具调用、没等到这条成功回执 = **没迁走**。
3. 对话的工作区路径已经变成该 Clio 主树。还显示 `F:\ai工作区\...` = **没迁走**。
4. `git -C C:\OneHistory\HistoryClio\<该模块主树> branch --show-current` 输出必须是 `main`。
5. **F 盘工作区目录此时必须还在。** 迁根工具要在里面 detach。目录已经没了就不要再迁、不要再 `finish`。
6. **工作区仍是登记中的 git worktree**（下面「finish 前严格检查工作区」A–D 全部通过）。只看到迁根回执、没把检查输出留在对话里 = **没检查** = 禁止 `finish`。

顺序只许是：**先迁走并确认 → 严格检查工作区 → 再 `finish`。** 先 `finish` 再迁 = 把对话钉死在已删路径上。迁根回执还没来就 `finish` = 同样钉死。只迁根、不检查工作区就 `finish` = 一样钉死：git 已卸登记、文件夹删不掉、之后迁根报 `not a git repository`。

其他 AI 不迁根。`finish` 前必须确认：本对话可见路径 **不是** 正在删除的那条 `F:\ai工作区\<项目>\<工作区>`。

- 可见路径就是那条工作区 → **禁止 `finish`**（会把本对话钉死）。grok 按手册迁到该模块 Clio 主树；其他 AI 不使用任何迁根或 Handoff 能力，换到根不在目标工作区的新对话处理。
- 可见路径是**另一条** F 盘残留目录、或根本不在 F 盘 → 删目标工作区不会拆掉当前根。跑 B–D 通过后可以 `finish`。**不要因为「路径里含 `F:\ai工作区`」就停住。**

人不要把 `F:\ai工作区\...` 加成 Cursor 主项目。

## 禁止：没把工作区检查结果留在对话里就 `finish`

**迁根回执不等于工作区已安全，更不等于可以 `finish`。**

`finish` 会先 `git worktree remove` 再删 `F:\ai工作区\<项目>\<工作区>`。下面任一为真，都会变成「目录删不掉 + 对话钉在半死路径上 + 再也迁不了根」：

- 本对话的可见工作区路径**就是正在 `finish` 的那条目录**（Cursor 项目钉在上面；或 grok 刚迁走、下一轮系统提示又跳回那条路径）
- 工作区 `.git` 已不是有效 worktree，但文件夹还在
- 有人把**该**工作区加成 Cursor 主项目，或编辑器仍打开其中的文件

**调用 `finish` 之前，必须在同一轮对话里把检查原始输出留在对话中。禁止用「刚才已经迁过根」代替本轮检查。**

- **grok：** 跑完 A–D。A 必须等于该模块 Clio 主树；仍含 `F:\ai工作区` = 没迁走，禁止 `finish`。
- **其他 AI：** 不跑 grok 的 A（不必把对话根迁到 Clio 主树）。先确认可见路径 ≠ 正在 `finish` 的工作区绝对路径，再跑 B–D。等于那条路径 = 禁止 `finish`。只是另一条 F 盘残留 = **不是**失败。

```
工作区 = F:\ai工作区\<项目>\<工作区名>
主树   = C:\OneHistory\HistoryClio\<该模块主树>

# A. 本对话当前可见工作区路径（Cursor 工作区 / 系统提示 / pwd）
#    grok：必须等于主树绝对路径。
#          仍含 F:\ai工作区 = 没迁走，禁止 finish。
#          刚收到 Moved agent root，但本轮可见路径又是 F 盘 = 没迁住，禁止 finish，重新迁根后再跑 A–D。
#    其他 AI：必须不是「正在 finish 的那条工作区」绝对路径。
#             等于那条路径 = 禁止 finish。
#             是另一条 F:\ai工作区\<项目>\残留、或 Vulcan / 其他模块主树 = 通过，继续 B–D。
#             不要把「可见路径含 F:\ai工作区」当成其他 AI 的禁止条件。

# B. 工作区目录还在，而且仍是 git 工作树
git -C "<工作区>" rev-parse --is-inside-work-tree
# 必须输出 true。false / fatal: not a git repository = 已经半删，禁止 finish，本轮按作废处理。

git -C "<主树>" worktree list
# 列表里必须仍有那条 F 盘路径。没有 = git 已卸登记、文件夹可能还在，禁止 finish。

# C. 工作区干净、仍在功能分支
git -C "<工作区>" status --porcelain
# 必须空。有输出 = 先 vulcan.dev.submit，不要 finish。

git -C "<工作区>" branch --show-current
# 必须是 ai/<项目>/<工作区名>

# D. 主树在 main
git -C "<主树>" branch --show-current
# 必须是 main
```

人侧：不要把 F 盘工作区加成 Cursor 主项目；若编辑器还开着该文件夹里的文件，先关掉，再让 grok 跑 A–D 和 `finish`。

只发了 `move_agent_to_root`、或只看到 `Moved agent root`、没有 A–D 输出 = **没检查工作区** = 禁止 `finish`。

## 禁止：停宿主

模块开发**不许停、杀、重启 HistoryVulcan 进程**。热重载不关宿主；目录锁了也不准拿宿主开刀。

`vulcan.svc.stop`、`vulcan.svc.restart`、`vulcan.app.quit` 是 **ask**：要等人在界面上点确定。AI 从 `--cli` 调这些指令会一直挂着等人工确认，对话就卡死。`Stop-Process` / 任务管理器杀 `HistoryVulcan.exe` 同样禁止——管线三条命令都假定宿主活着；杀掉以后 `--cli` 要么拉不起、要么空等。

工作区删不掉、DLL 占用、finish 卡住：看手册「卡住时看哪里」。不要停宿主碰运气。替换正式 `HistoryVulcan.exe` 才需要停进程，那是宿主打包，由人做，不在模块开发管线里。

**五条硬规则：**

1. **只有 `agent=grok` 迁根。** 其他 AI 一律留在当前对话根，按绝对路径访问 F 盘工作区；不得使用 Handoff 或任何同类能力代替。
2. **开发管线只给模块。** 宿主禁止走开发管线，不得调用 `vulcan.dev.start` / `submit` / `finish`，也不得把 `vulcan.worktree.*` / `vulcan.release.cycle` 当模块开发流程来用。
3. **开发管线只走 Console CLI。** 三条步骤只调同目录 `HistoryVulcan.Cli.exe --cli …`。不要直接调用内部的 `vulcan.worktree.*` 或 `vulcan.release.*`。
4. **grok：`finish` 之前必须先把对话根迁回模块主树的 `main`，确认迁走成功，再严格检查工作区（文首 A–D）。** 其他 AI 不迁根，但必须确认可见路径不是正在 `finish` 的那条工作区，再跑 B–D。迁根回执不能代替工作区检查。未确认或未检查就 `finish` 的对话作废，不要指望事后迁根补救。
5. **不许停宿主。** 见上文「禁止：停宿主」。不要 `vulcan.svc.stop` / `restart` / `vulcan.app.quit`，不要杀进程。那些要人工确认，会把这一轮卡住。

> **归属变更（宿主 4.6.0）。** 这条开发路线此前住在 HistoryDiana。现在引擎在宿主进程内，公开面是下面三条 `--cli` 指令。路线留在模块里会让「修模块」依赖那个模块自己装载成功；放在宿主则只要宿主活着，任何一个模块坏掉都能单独修好。
>
> 命令行在宿主进程内直接执行。开发管线不依赖外置服务；连模块装载都坏掉时，还有 `HistoryVulcan.exe --install-module <包目录>`。

模块日常只走三条命令。故意牺牲细拆灵活性，换稳定和少烧 token。
`HistoryVulcan.Cli.exe` 与正在运行的 `HistoryVulcan.exe` **同目录**。正式发布位是
`C:\OneHistory\HistoryClio\2026-023-HistoryVulcan\z-Publish\host\HistoryVulcan.Cli.exe`。
`msg=` 不要含空格（命令行按空格拆参数，空格会变成多余位置参数）。
Windows 控制台若仍乱码，先 `chcp 65001`；CLI 自身按 UTF-8 写 stdout。

| 步 | 命令行 | 做什么 |
|---|---|---|
| 1 | `HistoryVulcan.Cli.exe --cli vulcan.dev.start …` | 开分支和工作区 |
| 2 | `HistoryVulcan.Cli.exe --cli vulcan.dev.submit …` | 发到 z、提交、热重载到活宿主。**第一轮在这里停**，等人审批。未通过就继续改、再 submit |
| 3 | `HistoryVulcan.Cli.exe --cli vulcan.dev.finish …` | **仅审批通过后**：再发 z、提交、并回 main、删工作区、注册到宿主 |

内部仍是原来的 worktree/cycle/merge，模块不要直接调那些内部指令。`submit/finish` 负责安装运行包；不要手工拷 AppData 或改发现根，也不要把工作区路径 `publish=true` 到正式 Clio 槽。

**工作区边界：AI 长期只在宿主 `vulcan.dev.start` 开出的 `F:\ai工作区` 工作。** Janus、Mercury、Minerva 等模块仓库
主线是源码基线、合并目标和正式发布来源，不是 AI 的日常编辑目录。由 `vulcan.dev.start` 从主线拉出分支，
所有真实改动都在 F 盘工作区。HistoryDiana 与其它模块相同，也走工作区，不要直接改主线。

**不要把 AI 工作区当成 Cursor 项目打开。** `F:\ai工作区\<项目>\<工作区>` 只给 AI 改文件，不是给人
File → Open 的仓库。Cursor 把该目录当主项目打开后会独占路径，`vulcan.dev.finish` 删目录会
Permission denied。grok 用 `move_agent_to_root` 迁对话根不是「打开项目」。人只打开 Diana 或
模块 Clio 主树。

本手册只负责**流程**：从开工作区到正式发布，每一步用哪条命令、卡住时看哪里。
**接口事实不在这里**——模块注册与命令契约以 `HistoryVulcan_模块API.md` 为准，读法见下一节。

## 宿主给模块什么（5.0）

5.0 起宿主冻结面只剩三件事：**注册器**、**命令总线**、**开发总线**（只给模块用的 `--cli vulcan.dev.start/submit/finish`，引擎留在宿主，不外迁到 Diana）。宿主自己禁止走这条开发管线。

装载时 `IModuleContext` 只给 `Bus` 和 `RegisterCommands`。不要实现 `IUiModule` / `IShellUi*`，也不要读上下文上的设置、日志或数据根——那些成员已删除。要设置或数据根，走 `vulcan.app.get` / `set` / `opendata`，或自己的模块域命令。

窗格：登记普通命令，带 `ui.*` 注解（键由 Aurora 定义）；活对象放 `CommandResult.Data`。布局是 Aurora 的命令。未装界面模块时 `vulcan.ui.*` 是未知指令。公开类型和命令命名见 `HistoryVulcan_模块API.md`。

## 先学会查文档

跨项目读已发布文档时，**默认且优先走 Diana MCP**；模块开发操作仍只走 Vulcan Console CLI。
两条通道不要混：`diana.docs.*` 负责发现和读取正式文档，不在 `--cli` / `--runtime` 名单里；
`vulcan.dev.start` / `submit` / `finish` 负责开发工作区，不走 MCP。

文档读取顺序固定如下：

1. 先调用 `diana.docs.catalog`，把完整输出留在当前对话。
2. 从 catalog 输出复制目标项目的 `diana.docs.<通道>` 和相对 `file=`；长文加
   `heading=<章节标题>`，只读取当前需要的章节。
3. 不得猜通道、猜文件路径、维护手写文件表，也不得用邻接项目的 `b-Office/current`、
   `package` 或 worktree 代替已发布合同。

只有 **Diana MCP 工具未暴露或调用失败**时，才允许降级。降级前必须在对话里记录具体原因
（例如工具列表没有 Diana、鉴权失败或调用超时），然后只读目标项目正式 `z-Publish/docs`；
不得转去扫描邻接源码树。若连正式 Z 文档也无法确定，停止读取并报告缺失，不自行猜路径。

`HistoryVulcan.Cli.exe` 与正在跑的宿主同目录，发布位通常是
`z-Publish\host\HistoryVulcan.Cli.exe`。查 start/submit 的参数用
`--cli vulcan.cli.show name=vulcan.dev.submit`（列出必填/可省略参数），或 `vulcan.command.show`。

开发模块时最常查的几份：

| 想知道 | 去哪查 |
|---|---|
| 本手册、宿主 API | catalog 返回的 Vulcan 通道；工具不可用时才降级到 Vulcan 正式 `z-Publish/docs` |
| 能注册什么窗口、页面怎么嵌 | catalog 返回的 Aurora 通道与其中的正式 UI 合同 |
| 别的模块对外暴露了什么 | catalog 返回的该模块通道；不得打开它的 current/package/worktree |

## AI 前端图形查看：先 Diana，不抢鼠标

只读观察桌面 UI（截图、布局/文字核对、重叠或空白区域检查）默认且优先走 Diana 后台捕获：

1. 调用 `diana.view.windows`，从返回结果确认目标窗口和句柄。
2. 调用 `diana.view.capture handle=<窗口句柄>`；省略 `handle` 时由 Diana 选择可见客户区最大的窗口。
3. 用图像查看工具实际打开并读取返回的 PNG，同时保留窗口尺寸、捕获方式和 SHA。
4. 修改交互界面时，至少在修改前后各捕获一次，用实际图像核对变化、重叠和空白区域。

Diana 后台捕获不移动鼠标、不切换前台。**禁止为只读观察调用 Computer Use、点击窗口、
移动鼠标或抢占前台。** 返回窗口清单或 PNG 路径本身不等于视觉验证；AI 必须实际读取图像。
只有任务确实需要点击、输入或拖拽时才使用 GUI 控制。

若 Diana View 工具未暴露或调用失败，先在对话中记录具体原因，不得静默切换到 Computer Use
或其它 GUI 控制。任何会接管鼠标或前台的替代方案都必须先取得用户明确同意。

## 一轮怎么走

人发起一轮更新。AI 先把不清楚的问完（Cursor 询问工具），再开工作区。第一轮做到
**工作区 `submit` 成功、模块已热重载进活宿主**就停，等人审批。不要在同一次对话里擅自 `finish`。

```
人发起更新
        ↓
AI 用询问工具问清模块、范围、版本（没有不清楚的就跳过）
        ↓
【命令 1】HistoryVulcan.Cli.exe --cli vulcan.dev.start project=<项目> slug=<问题> agent=<ai>
        开分支和工作区（仅模块；宿主禁止）
        ↓
【grok 必须】四步把对话根搬进该工作区（见「一、开工作区」）
其他 AI 不要迁根，按 start 返回的绝对路径改文件
        ↓
       只在该工作区改代码
        ↓
【命令 2】HistoryVulcan.Cli.exe --cli vulcan.dev.submit name=<模块> msg=<说明> worktree=<工作区> [allowDirty=true]
        门禁 → 写该工作区 z → git commit → 安装并热重载到运行宿主
        工作区有任何未提交改动都要 allowDirty=true（不只是改版本登记）
        ↓
       门禁未过 → 继续改 → 再 submit
       门禁过、已部署 ↓
【第一轮结束】停。把工作区路径、版本、运行核对结果交给人。
        ↓
人审批不通过 → 仍在该工作区改 → 再 submit（还是第一轮的续轮，不要 finish）
人审批通过 ↓
【grok 必须】先 `move_agent_to_root` 到该模块 Clio 主树 `main`，等到迁根成功回执且对话路径已离开 `F:\ai工作区`。未确认迁走 = 禁止 finish。
【其他 AI】不迁根。确认可见路径不是正在 finish 的那条工作区后跑 B–D。可见路径只是另一条 F 盘残留 ≠ 禁止。
        ↓
【命令 3】HistoryVulcan.Cli.exe --cli vulcan.dev.finish name=<模块> msg=<说明> worktree=<工作区>
        复用已提交候选、并回 main、删工作区、核对运行包
        ↓
       回到 main
```

主树 `publish=true` 只用于正式 Clio z。不要把工作区路径传给 `publish=true`。
`submit` 成功不是合并许可。没有人的通过，禁止 `finish`。

## 一、开工作区

```
HistoryVulcan.Cli.exe --cli vulcan.dev.start project=2026-021-HistoryMercury slug=explorer-notify agent=claude
```

得到 `F:\ai工作区\<项目>\<短SHA>-<序号>-<标识>`，分支 `ai/<项目>/<同名>`。
序号跳过已有目录，也跳过 finish 留下的同名分支（**分支一律保留**）。同一 slug 再 start 会得到 `-2-`，不必换 slug，也不要删旧分支。

同时会在工作区里生成 `Directory.Build.user.props`，把 `HistoryVulcanPackageRoot` 指回来源库根。
各工程按相对路径引用宿主快照，而工作树落在库根之外，少了这个覆盖点会报上百个「找不到类型」。
该文件不入库（各项目 `.gitignore` 已登记），所以工作区从诞生起就是干净的。

- **不要在模块主树上改**。主树是发布和对照的基准；工作区是 AI 的唯一日常编辑面，分支提交可再生但
  主树提交是正式发布来源。
- 工作区根由 `vulcan.dev.start` 决定（默认 `F:\ai工作区`）。不要改调隐藏的 `worktree.root`。
- `vulcan.dev.start` 在已有闲置工作区时默认拒绝再开；并行才传 `confirm=true`。
**切根只适用于 grok，而且是 grok 必须做的一步，不是可选项。** 只有 `agent=grok` 获准使用 Cursor 的 `move_agent_to_root`。
其他 AI 不要尝试迁对话根，也不要把「没切根」当成流程失败：即使产品提供 Handoff 或同类能力也不得使用；对话留在当前根，按 `start` 返回的绝对路径改 F 盘工作区。
grok 若跳过切根、人若把工作区加成 Cursor 项目，都会把后续 finish 卡住或把改动写到错误的树。

**人不要打开 AI 工作区当项目。** 不要把 `F:\ai工作区\...` 加成 Cursor 窗口或主项目。那会锁住目录，合并后删不掉。

### 搬进工作区（grok 必须）：先切目录，再切分支

其他 AI 不要执行本节。开完工作区不等于对话已经在里面。**grok 必须把对话根搬进这个工作区**——这是故意要做的，必须忍受。
Cursor 把对话根迁到目标目录时，会在目标里执行 `git checkout main`。Git 规定**同一条分支同一时刻
只能被一个 worktree 占用**；模块主树已经占着 `main`，于是迁根直接失败：

```
fatal: 'main' is already used by worktree at C:/OneHistory/HistoryClio/<模块主树>
```

这不是脏工作区，提交再干净也过不去。也不是「不该迁根」或「Git 不允许开工作区」——工作区本来
就该停在 `ai/<项目>/<工作区名>` 上，主树才该占 `main`。迁根工具会去抢 `main`，所以用下面四步
把它让开，而不是放弃迁根。

**不要**为了躲开这条报错而不搬对话根。**不要**在工作区里先 `checkout main` 来「配合」迁根。
**不要**把对话留在模块主树再改（那是日常编辑主线，违规）。**不要**把主树长期停在 detached HEAD。

规定顺序是**先让开主树的 main，把对话根落到工作区目录，再把工作区切回功能分支，最后把主树 main 复原**：

```
# 1. 主树临时让开 main（两边若还在同一 SHA，工作区文件不会变）
git -C C:\OneHistory\HistoryClio\<模块主树> checkout --detach

# 2. 把对话根迁到 F:\ai工作区\<项目>\<工作区名>
#    （仅 grok：move_agent_to_root。其他 AI 未获迁根授权，不要用 Handoff、切换项目或打开文件夹代替）

# 3. 工作区切回功能分支（迁根工具可能已经把它切到 main，必须切回来）
git -C F:\ai工作区\<项目>\<工作区名> checkout ai/<项目>/<工作区名>

# 4. 主树立刻回到 main
git -C C:\OneHistory\HistoryClio\<模块主树> checkout main
```

四步做完应是：对话根在 F 盘工作区、该树在 `ai/...` 分支、主树仍在 `main`。任何一步失败都先把主树
`checkout main` 复原，不要留下 detached 主树。

HistoryDiana 与其它模块相同，也走这四步。不要把「造工作区的工具不能用工作区改自己」再当成例外——
开发管线已在宿主进程内，Diana 只是一个 `kind=module` 的消费方。模块入口是 `vulcan.dev.submit` / `finish`，不要再找 PowerShell 发布脚本，也不要直接调 `vulcan.release.cycle`。

## 二、改代码

模块对宿主的依赖面是**已发布的 z 快照**，不是宿主源码树。

这不是洁癖，是踩过的坑：Mercury 4.5.1 的 csproj 写的是「只要宿主源码树存在就引用源码工程」，
于是宿主工作区一有未发布的在途改动，模块就链接到根本没在运行的宿主二进制，
装载时在 WPF 视图构造处抛 `XamlParseException: 设置 connectionId 时引发了异常`，
宿主只记一行 Warn 继续走，**桌面坞从桌面上无声消失**。

所以新模块的 csproj 应当：

- 默认 `HintPath` 引用 Vulcan 4.0.0 的平铺宿主快照 `z-Publish/host/HistoryVulcan.*.dll`，`<Private>false</Private>`；
- 要对宿主源码联调时**显式**传 `-p:HistoryVulcanSourceAvailable=true`，不做自动切换；
- 加一个前置校验目标，两条路径各自检查前提缺失时直接报错，而不是报成一堆「找不到类型」。

普通模块自己的候选仍使用版本化目录 `z-Publish/HistoryX-vX.Y.Z/`；只有宿主当前快照使用
`z-Publish/host/` 平铺形状，旧宿主包只能从 `z-Publish/history/` 取用。模块构建前先确认平铺
`manifest.json` 的 `product=HistoryVulcan`、版本和 `SHA256SUMS` 与 `host/HistoryVulcan.exe` 存在。
`HistoryAurora` 已在宿主 `module-publish.manifest.json` 登记为 `kind=module`，走
`vulcan.dev.submit` / `finish`。Diana 不发布，不得再以「不接受 `-OutputRoot`」排除任何模块。

可用 `b-Code-Samples/` 下的 DemoModule 作为起点（`ModuleInfo`、命令类、`.panel.json`）。

另一条同源的坑：**测试工程不会从模块工程传递 `HintPath` 引用**。模块侧从
`ProjectReference` 改成 `Reference` 之后，Smoke 必须自己声明需要的宿主程序集。

工作区合同会解析 Markdown 链接。不要写成指向 Clio 兄弟仓的相对链接
（例如 `../2026-023-HistoryVulcan/...`）：F 盘工作区不是 HistoryClio 的兄弟目录，门禁会报 Broken Markdown link。
跨仓路径用反引号写明仓库与文件，不要做成可点击链接。

## 三、一轮：门禁、写入工作区 z、提交、送审（第一轮在这里停）

```text
HistoryVulcan.Cli.exe --cli vulcan.dev.submit name=HistoryMercury msg=说明 worktree=<工作区名或绝对路径>
```

`worktree=` **必填**：传 `vulcan.dev.start` 返回的绝对路径，或该项目在 AI 工作区根下的目录名。
描述符禁止省略——省略会走到主树正式促级，模块开发不要走那条。
这条命令一次做完：构建、合同、Smoke、把已验证候选写入**该工作树自己的**
`z-Publish/HistoryX-vX.Y.Z`、`git commit`，再经活宿主 `vulcan.module.install` **只重载这一个模块**。
写 z 和热重载是同一条 `submit`，不要再调隐藏的 `vulcan.release.cycle`，也不要单独
`--cli vulcan.module.install`，更不要 `--runtime vulcan.module.reload`（那会拆掉全部模块，界面指令可能归零）。
工作区同版本再 submit：新内容替换该工作区当前候选（旧内容进 `history/`），不必为了覆盖而升版本。
主树正式促级仍不可变。
`submit` 必须拿到活宿主回执「已热重载到活宿主」才算成功。离线组合写 AppData 不算。活宿主不可达则失败，不降级。
未通过就继续改、再 submit。门禁通过且热重载成功后**第一轮结束**，把工作区路径和运行版本交给人。没有人的通过，禁止 `finish`。

工作树默认必须干净。有任何未提交改动（不只是版本登记）都要传 `allowDirty=true`，管线会在回执中列出
授权文件摘要。`msg` 不能含空格，用连字符。Windows PowerShell 5 不要给 `Tee-Object` 加 `-Encoding`。
`dryRun=true` 只输出项目、测试、候选路径、运行目标和副作用，不构建、不写文件、不提交、不热重载。
登记为 `kind=module` 的条目都可以带 `worktree=`。宿主（`kind=host`）禁止走 submit/finish。

门禁包括：候选构建、Diana 强制对齐的模块合同、以及登记表里为该模块配置的验证（通常是 Smoke）。
**门禁拦下来时，优先改代码，不要改门禁的期望值**——除非那个期望本身描述的就是过时的事实
（例如新增了一个命令类、模块版本号变了）。这类修正要在提交信息里说明为什么。

## 四、候选安装与运行核对

`submit` 和 `finish` 在构建、合同测试、候选校验及提交成功后，把刚写入的版本化候选
经活宿主 `vulcan.module.install` 装进运行区并**只重载同名那一个模块**。安装仍校验
`module.manifest.json` 与完整 `SHA256SUMS`，采用 staging、原子替换和失败恢复。
不要手工拷贝 AppData，也不要从宿主源码树拼包。不要 `--runtime vulcan.module.reload`
（那会拆掉全部模块；界面模块可能变成 0 条指令）。

自动化脚本在管线返回成功后，用运行时查询核对：

```text
HistoryVulcan.Cli.exe --runtime vulcan.module.list --format json
```

JSON 包装的 `data` 是模块目录（`moduleName` / `version` / `instanceId` / `commandCount`）。
`runtimeAck.modules` 是同一份摘要（`name` / `version` / `instanceId` / `commandCount` / `attached`）。
`runtimeAck.moduleInstanceIds` 只是 ID 列表，没有名字和版本。不要只看 json 包装本身。
人眼核对也可以去掉 `--format json`，读文本行 `HistoryJanus 5.4.8 (41 条指令)`。

成功判据（同版本覆盖时版本字符串可以不变）：

1. submit 回执含「已热重载到活宿主」
2. `data` 或 `runtimeAck.modules` 里该模块 `instanceId` 已变（或版本已升）
3. 其它模块（尤其 HistoryAurora）的 `commandCount` 不得变成 0

版本未变但 2、3 成立 = 同版本热重载成功，不要误报失败。回执不是「已热重载到活宿主」就是失败。

## 五、并回主线

**停。先读文首两条禁止，再跑「finish 前严格检查工作区」A–D。没有把 A–D 输出留在本轮对话里，禁止 `finish`。**

`finish` 会删除工作区目录。对话根还在该目录、迁根回执还没到、或工作区 git 已半死，就调用 `finish`：Cursor 占着路径删不掉，或 git 已卸登记、文件夹还在。之后 `move_agent_to_root` 必在已死路径上 `git checkout --detach`，报：

```
fatal: not a git repository (or any of the parent directories): .git
Cannot migrate: failed to detach worktree HEAD
```

**这一轮对话作废。不要再迁根，不要再对那条 F 盘路径跑 git。** 人关对话，新开对话打开该模块 Clio 主树 `main`。

工作区被当成 Cursor 主项目打开时，同样 Permission denied，留下「git 已卸登记、文件夹还在」的残骸。

审核通过、工作区干净且 `submit` 已提交后，grok **必须先迁根、等成功回执、确认对话路径已是 Clio 主树、再跑文首 A–D 并把输出留在对话里，最后才 finish**（顺序不能反，不能跳过 A–D）。
没有人的通过就调用 `finish` = 跳过审批。没有 A–D 输出就调用 `finish` = 没检查工作区。

```
# 1. 模块 Clio 主树必须已在 main（开工作区第四节已复原；若不是，先复原）
git -C C:\OneHistory\HistoryClio\<模块主树> checkout main
git -C C:\OneHistory\HistoryClio\<模块主树> branch --show-current   # 必须是 main

# 2. 把对话根迁到该模块 Clio 主树（仅 grok：move_agent_to_root）
#    此时 F 盘工作区目录必须还在，迁根工具要在里面 detach。

# 3. 确认对话已不在 F:\ai工作区\... ；主树当前分支是 main
#    若迁根工具在主树建出 ai/... 分支：立刻 checkout main 并删掉误建分支

# 4. 系统已回 Moved agent root to C:\OneHistory\HistoryClio\<模块主树>
#    对话工作区路径已不再含 F:\ai工作区

# 5. 严格检查工作区（文首 A–D），输出留在本轮对话
#    可见路径、rev-parse、worktree list、porcelain、工作区分支、主树 main
#    全部通过后才允许 finish
```

缺第 4 步或第 5 步就调用 `finish` = 把对话废掉。迁根失败或 A–D 任一失败时禁止 `finish`。

其他 AI 不迁根。确认本对话可见路径不是正在 `finish` 的那条工作区后，跑文首 B–D，通过后再 finish。可见路径是另一条 F 盘残留目录 ≠ 失败：

```text
HistoryVulcan.Cli.exe --cli vulcan.dev.finish name=HistoryMercury msg=说明 worktree=<工作区目录名>
```

若可见路径就是正在删除的那条工作区：禁止 finish。grok 按本节迁到该模块 Clio 主树；其他 AI 不使用任何迁根或 Handoff 能力，换到根不在目标工作区的新对话。不要把「路径里含 F:\ai工作区」当成禁止。

finish 会再发 z、提交、并回 main、删除工作区目录、把主线候选注册到宿主。对话根还留在里面时，目录一删，这轮对话就废了：之后的迁根会在已删除路径上跑 git，直接失败，且无法从对话内迁走。
grok 迁到别的仓库后立刻 `git branch --show-current`：迁根工具可能在目标仓建出源工作区的 `ai/...`
分支，这时 `checkout main` 并删掉误建分支，不要在别人的分支名下改这个仓库。

删不掉通常不是切根问题：有人把该工作区目录当成 Cursor **主项目**打开了。先关掉那个项目窗口，
再 merge 或删目录。grok 迁对话根不必为此改到某个固定仓；迁到当前还要继续改的那棵主树即可。

主树必须在 `main`。优先快进，不能快进则 `--no-edit` 合并。合并后从主线解析唯一版本化候选，
调用 `vulcan.module.install` 热重载运行包，再删除工作区目录。

主树 z 来自合并过来的工作区候选 z，不是从工作树再跑一次 `publish=true`。
`publish=true` 仍只允许主树（正式促级）。

Diana 不提供 push 或建 PR。

促级前必须对齐三处身份，否则管线直接拒绝：

| 位置 | 内容 |
|---|---|
| 版本源 | csproj 的 `Version` 或 `<模块>Version.props` |
| 源清单 | `b-Code-*/module.manifest.json` |
| 快照清单 | `z-<模块>/module.manifest.json`（由管线写入） |

新模块要能被管线发布，需在宿主仓 `b-Code-Eng/pipeline/module-publish.manifest.json`
登记一项（`kind=module`），并提供构建脚本。可直接照抄任一现有模块的构建脚本逐词替换——
事务结构（stage/backup/failed + 校验和清单）必须保持一致。
不要在宿主源码里为新模块加名字名单；登记表是唯一入口。

## 六、先部署后提交

**顺序是先部署、后提交，不能反过来。** `vulcan.dev.submit` / `finish` 已经按这个顺序做完：
门禁和写 z 成功之后才 commit。不要先手工提交再走管线。不要用宿主的 `release.cycle` 代替模块 submit。

候选热重载失败不回滚已经成功的提交。继续改代码后再 submit，或由人工选择主树候选/历史包恢复。

工作区改动并回主干用 `vulcan.dev.finish`；不要先手工 merge 再删工作区。
闲置、与 main 齐平的工作区也用 `finish` 回收。分支一律保留。Diana 不 push、不建 PR。

## 七、宿主禁止走本管线

本手册是**模块**开发管线。HistoryVulcan 宿主禁止使用：

- 不得 `--cli vulcan.dev.start` / `submit` / `finish`
- 不得把 `vulcan.worktree.create` / `merge` / `release.cycle` 当成「宿主版开发管线」来走

改宿主源码、打宿主包，不在本手册范围内。模块 AI 不要对 `2026-023-HistoryVulcan` 调 start。

宿主若要写入 z 候选，那是发布入口 `HistoryVulcan.Cli.exe --cli vulcan.release.cycle name=HistoryVulcan …`，不是模块开发管线。

不要 `vulcan.module.install` 宿主快照，不要改模块根去“装”一个新宿主。**模块开发不许停宿主**（见文首「禁止：停宿主」）。`vulcan.svc.stop` / `restart`、`vulcan.app.quit` 要人工确认，AI 一调就卡。替换正式 `HistoryVulcan.exe` 才需要停进程，那是人做的宿主打包，不是模块管线。

## 卡住时看哪里

| 现象 | 先看什么 |
|---|---|
| submit/finish 一直不返回 | 看宿主日志末尾；管线可能已死在某一步。**不要停宿主等它醒** |
| 调了 `vulcan.svc.stop` / `restart` / `vulcan.app.quit` 一直不返回 | 在等人工确认。取消这次调用。模块开发禁止这些指令 |
| 工作区删不掉就去杀 HistoryVulcan | 禁止。占用多半是 Cursor 窗口，不是宿主。停宿主要人工确认，会卡，也解不开 Cursor 的锁 |
| 重载后模块未出现 | 包 manifest/SHA 是否完整，程序集身份是否与目录名一致；查看 Vulcan 模块日志 |
| 门禁报「模块版本 expected≠actual」 | 三处身份没对齐 |
| 促级后宿主没换新 | 回执须含「已热重载到活宿主」；`--format json` 看 `data` 或 `runtimeAck.modules` 里该模块 instanceId/版本。Aurora 的 commandCount 不得变 0。不要 `--runtime reload` |
| json 里没有模块名/版本 | 看 `data` 或 `runtimeAck.modules`，不是 `moduleInstanceIds`。也可以去掉 `--format json` |
| `vulcan.cli.show` 没有参数 | 当前版本会列出参数。若仍没有，改用 `--cli vulcan.command.show name=vulcan.dev.start` |
| 把 `diana.docs.catalog` 传给 CLI/runtime 后被拒绝 | 走错通道；改用 Diana MCP。若 Diana 工具未暴露或调用失败，记录原因后才降级读正式 Z 文档 |
| Diana MCP 鉴权失败或调用超时 | 记录原始失败；不要改走 CLI/runtime。按本节规则只读目标项目正式 `z-Publish/docs` |
| 只想看界面却准备调用 Computer Use | 停止 GUI 控制；先用 `diana.view.windows` → `diana.view.capture` 后台抓图，再实际读取返回的 PNG |
| `diana.view.capture` 返回了 PNG 路径 | 还未完成视觉验证；用图像查看工具读取 PNG，并记录尺寸、捕获方式和 SHA |
| Diana View 未暴露或捕获失败 | 记录具体原因，不得静默抢鼠标或前台；需要 GUI 控制时先取得用户明确同意 |
| 版本号没变 | 同版本覆盖时版本可以不变。看该模块 instanceId 是否变、Aurora 指令数是否仍 > 0 |
| submit 后 Aurora 变成 0 条指令 | 旧宿主整仓 Reload 的毛病。当前 install 只装这一个模块。若仍是 0，人侧重启宿主（模块开发不要自己停） |
| `a branch named 'ai/...' already exists` | 旧 start 只数目录、撞上 finish 留下的分支。当前会自动改用下一个序号。若仍失败，换 slug，不要删分支 |
| 报「历史包已存在且内容不同」 | 工作区 submit 应能覆盖同版本当前候选。若仍出现，是主树正式促级，需要升版本 |
| 桌面上的 UI 消失但命令还在 | 宿主日志搜「创建 UI 模块 ... 失败」，多半是建界面时抛异常 |
| 测试候选不通过 | 手动选择主树候选或 `z-Publish/history/HistoryX-vX.Y.Z` 再次重载；不会自动恢复 |
| 合并后工作区删不掉 / DLL 被占用 | 确认安装操作已结束；工作区包不是运行槽，Vulcan 运行副本应只在 AppData |
| finish 后工作区 Permission denied | 对话根或 Cursor 主项目还占着该路径。先确认对话已在 Clio 主树；人关掉仍打开该文件夹的窗口再删。不是切根、也不必先迁 Diana |
| finish 前没跑工作区检查 / 只看了迁根回执 | grok 禁止 finish。先迁根，再跑文首 A–D。其他 AI 先确认可见路径 ≠ 目标工作区，再跑 B–D。`rev-parse` 不是 true、或 `worktree list` 没有那条 F 盘路径：禁止 finish |
| 可见路径是另一条 F 盘残留，不是正在 finish 的工作区 | 其他 AI 不要停。确认路径 ≠ 目标工作区后跑 B–D，通过就 finish。不要把「含 F:\ai工作区」当成检查 A 失败 |
| finish 后迁根报 `not a git repository` / `failed to detach worktree HEAD` | **对话已经废了。** 当前根是已删或半删的 F 盘工作区。不要再 `move_agent_to_root`。人关对话，新开对话打开该模块 Clio 主树 `main`。下次 finish 前必须先迁根、再严格检查工作区 A–D |
| 想看候选却去改 roots / 手工拷 AppData | 改用 `vulcan.module.install path=<完整包目录>` 或模块页「热重载」 |
| 对宿主调 `vulcan.dev.start` | 对。宿主禁止走开发管线 |
| 文档通道把整本手册灌进对话 | 长文加 `heading=章节标题`，只读取当前需要的章节 |
| 切根报 `main is already used by worktree` | **仅 grok。** 迁根工具会抢 `main`，按第一节四步：主树 detach → 迁根 → 工作区切回 `ai/...` → 主树 `checkout main`。其他 AI 不要切根 |
| finish 后迁根报 ENOENT / spawn git 失败 | **仅 grok。对话已废。** finish 已删工作区。应在 finish **之前**把对话根迁走并确认成功。现在只能关对话、换新对话打开 Clio 主树 |
| 迁根报 `not a git repository` / `failed to detach worktree HEAD` | **仅 grok。对话已废。** 当前根是已删或半删的工作区。不要再迁根。人关对话，新开对话打开该模块 Clio 主树 `main` |
| 迁根后当前分支是其他项目的 `ai/...` | **仅 grok。** 迁根工具把源分支名建到了目标仓。立刻 `checkout main`，删掉误建分支 |

## 相关命令一览

| 命令 | 用途 |
|---|---|
| `--cli vulcan.dev.start` | 模块第 1 步：开分支和工作区。禁止宿主 |
| `--cli vulcan.dev.submit` | 模块第 2 步：写工作区 z、提交、经活宿主 install 热重载。禁止宿主 |
| `--cli vulcan.dev.finish` | 模块第 3 步：再发 z、并回 main、删工作区、核对运行包。禁止宿主 |
| `--runtime vulcan.module.list [--format json]` | 查询活宿主。json 的模块目录在 `data` / `runtimeAck.modules` |
| `--cli vulcan.cli.show name=…` | 查 CLI 指令的参数和执行边界 |
| `diana.docs.*` | 跨项目正式文档的默认入口，只走 Diana MCP；不属于 CLI/runtime 开发管线 |
| `diana.view.windows` | 后台列出可捕获窗口；只读观察 UI 时先调用 |
| `diana.view.capture handle=<句柄>` | 后台捕获窗口 PNG，不移动鼠标、不切换前台；返回后还必须实际读取图像 |

## 工具提示

给模块开发 AI 的最小可复制提示：

