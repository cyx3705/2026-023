## 这次升级到底变了什么

一句话：**宿主拆成了两个产品。**

| | 升级前 | 升级后 |
|---|---|---|
| 进程 | `HistoryVulcan.exe` 一个 exe 两个角色（前端 / `--service`） | `HistoryVulcan.exe` 无头服务 + `HistoryAurora.exe` 前端 |
| 界面代码 | 宿主 `HistoryVulcan.Shell`（11,545 行） | Aurora `b-Code-Studio/Shell` |
| 样式键 | `Shell.*` | **`Aurora.*`** |
| 前端命令 | `vulcan.ui.*` / `vulcan.log.*` … | **`aurora.ui.*` / `aurora.log.*` …** |
| 宿主版本 | 3.13.0 | **4.0.0** |
| Aurora 版本 | —— | **1.0.0** |

对模块的影响按大小排序：**样式键改名 > 命令改域 > 宿主 API 删除**。
最后一项对四个模块几乎无影响——实测下来只有 Minerva 有一处真的要改。

## 一、样式键 `Shell.*` → `Aurora.*`（影响最大）

65 个设计令牌 + 16 个具名样式全部改前缀，**家族结构与语义不变，只换前缀**。

```
Shell.Brush.TextPrimary   →   Aurora.Brush.TextPrimary
Shell.Segment.Bar         →   Aurora.Segment.Bar
Shell.GridHeader          →   Aurora.GridHeader
```

**没有 `Shell.*` 别名，没有弃用期**（Aurora DEC-005）。理由是别名本身就是技术债：
双键并存要维护两套、每次演进同步两处，且无法判断某个模块用的是哪一套；
而"弃用期"在实践中等于永久保留。

### 这个变更不会让你的模块崩溃——这正是危险之处

`DynamicResource` 找不到键时 WPF **不抛异常**，只是不套用该值。未适配的页面
**不报错，而是静默退化成 WPF 默认外观**：灰按钮、系统字体、与其余页面明显不一致。

不要指望编译器或运行时告诉你哪里漏了。用检查器：

```bash
grep -rn "Shell\.[A-Za-z.]*" <你的模块仓> --include=*.xaml --include=*.cs
```

返回空才算改完。**改完必须浅色深色各目视一次**——静默退化只能看出来。

### 改名操作

全仓替换 `Shell.` → `Aurora.`，但要避开三类误伤：

| 不能改 | 例子 | 原因 |
|---|---|---|
| 类型名 | `ShellWindow`、`ShellConfig`、`IShellUiAware`、`IShellLog` | 是 CLR 类型，不是资源键 |
| 命名空间 | `HistoryVulcan.Shell.Docking` | 同上 |
| 元素名 | `ShellChromeHost` | XAML 的 `x:Name` |

安全的做法是只替换 `Shell.` **后面跟大写字母且前面不是字母/点**的位置：

```
正则： (?<![A-Za-z0-9_.])Shell\.(?=[A-Z])
```

宿主自己迁移时就是用这条，466 处零误伤。

## 二、模块不得自建组件

模块 XAML **不得出现 `Style x:Key=` 与 `<ControlTemplate>`**（Aurora DEC-005）。

```bash
grep -rn 'Style x:Key=\|<ControlTemplate' <你的模块仓> --include=*.xaml
```

### 但这条禁令现在还不生效

实测三个模块的全部自建（2 个样式 + 4 个模板）**都源于同一个缺件**：
分段家族缺 Toggle 成员。`Aurora.Segment.Toggle` 是这条禁令的**解禁前置**——
它落地之前不会对模块执行该禁令。

所以本轮：**先把键名改完，自建的先留着**。等 Aurora 补齐缺件会另行通知，
届时删掉自建版本，外观不变。

唯一的例外是 `DataGrid`：它明确**不在主题化范围内**（Aurora REQ-UI-002）。
实测 12 个页面里 `ListView` 用 21 次、`GridViewColumn` 46 次，`DataGrid` 只有 2 次——
为它维护第二套表格外观不值得。用了 `DataGrid` 的页面需要自己改用 `ListView` + `GridView`，
这属于重画，不是改名，**不在本轮范围**。

## 三、命令改域 `vulcan.*` → `aurora.*`

37 条前端命令改域。如果你的模块在代码或文档里硬编码了这些命令名，要一并改：

```
vulcan.ui.*      →  aurora.ui.*        （21 条：窗口、布局、面板、文件选择）
vulcan.log.*     →  aurora.log.*       （10 条：控制台过滤与导出）
vulcan.app.about / opendata / theme / window  →  aurora.*
vulcan.command.copyexample / history          →  aurora.*
```

### 有一批**不能改**——它们是协议名不是实现名

| 保持 `vulcan.*` | 为什么 |
|---|---|
| `vulcan.app.close` / `show` / `hide` / `focusconsole` / `quit` | 宿主按**字面量**中继给前端，改了中继就断 |
| `vulcan.module.*` | 宿主安装/移除运行包时按名中继，让前端卸下同名 UI 快照（DEC-043）|
| `vulcan.command.list` / `show` / `domains` / `manual` / `help` / `run` | 由宿主实现，只是登记进前端进程 |
| `vulcan.svc.*` / `vulcan.mcp.*` / `vulcan.prompt.*` | 宿主自己的命令 |

判断依据是**这条命令由谁实现**，不是它讲的是什么主题。宿主迁移时就是按这条拆的。


### 怎么扫（2026-08-20 更正）

**本篇初版给的扫描命令是错的**，两处：模式只覆盖 `vulcan.ui|log`，漏了同样改域的
`vulcan.command.copyexample|history` 与 `vulcan.app.about|opendata|theme|window`；
且只搜 `*.md`，不搜代码。据此得出的"未硬编码"结论是无效的——实测 Mercury
有三处活代码命中（见其专属篇）。

正确的扫法，覆盖全部 37 条改域命令，且不会误伤保留 `vulcan.*` 的协议名：

```bash
grep -rnE "vulcan\.(ui|log)\.|vulcan\.app\.(about|opendata|theme|window)|vulcan\.command\.(copyexample|history)" <你的模块仓> --include=*.cs --include=*.xaml --include=*.md --include=*.json --include=*.ps1 | grep -v "/obj/\|/bin/"
```

### 命中了也可能"还能跑"，别被骗过去

旧名字**目前仍然解析得通**，但那不是因为它们还在——宿主源码里已经一处都没有。
是 `web.frontendcatalog` 那个按客户端名做键、不回收的缓存把退役名字复活了
（同一个 bug 让 `vulcan` 域至今虚报 66 条，实际 30）。

**该缓存是已知待办，一旦清理，所有旧名字立刻变"未知指令"。**
所以判断标准是扫描结果，不是"点下去还能用"。

## 四、宿主 API 变化（对模块影响很小）

4.0.0 移除了 162 个 `Services` 公开符号，但绝大多数是模块从不接触的内部面：
局域网接入（设备鉴权/配对/CORS/限流）、提示治理命令、旧发现接口。

实测四个模块中**只有一处真的要改**（Minerva 的 `CommandSchemaExporter`，见专属篇）。

若你的模块编译报 `CS0234 命名空间中不存在类型`，按下表对照：

| 症状 | 处置 |
|---|---|
| `CommandSchemaExporter` 找不到 | 从 `HistoryVulcan.Core.Mcp` 移到 **`HistoryVulcan.Extensibility.Mcp`**，改 using |
| `PromptGovernanceCommands` / `PromptProposal*` / `PromptStatus` | 提示治理已移出宿主，无替代；相关功能由外部工具承担 |
| `IDeviceAuthenticationProvider` / `DevicePairingResult` / `WebCommands` | 局域网面已删除，无替代 |
| `ModuleHost.GlobalShortcuts` / `IGlobalShortcutHost` | 全局快捷键改由提供方自持并经 `<域>.hotkey.*` 命令暴露 |

`Core.Mcp` 里仍然保留的：`IMcpAuditLog`、`McpExposurePolicy`、`McpConfirmationScope`、
`PromptTextIntegrity`、`GatewayAwareConfirmation`。

`IUiModule` / `IShellUiAware` **本轮不变**。它们会在 C 阶段（模块改用页面描述契约）删除，
那是另一轮，届时另行通知。

## 五、构建与运行

### 构建

模块对宿主的引用走 `z-Publish/host` 的文件引用。**升级前必须先刷新那份快照**，
否则你是拿新代码链旧 DLL：

```bash
cd ../2026-023-HistoryVulcan
powershell -NoProfile -ExecutionPolicy Bypass -File .\b-Code-HistoryVulcan\eng\Build-HistoryVulcanPackage.ps1
```

确认 `z-Publish/host/HistoryVulcan.Core.dll` 的 ProductVersion 是 `4.0.0`。

### 运行

现在要起**两个**进程：

```bash
# 1) 无头宿主（不带任何参数即为服务）
z-Publish\host\HistoryVulcan.exe

# 2) 前端
<Aurora>\b-Code-Studio\App\bin\Release\net8.0-windows\HistoryAurora.exe
```

宿主由 `vulcan.svc.autostart` 注册登录启动，正常情况下先于 Aurora 就绪。
**Aurora 不再派生后台**——它是另一个产品，不知道宿主装在哪，也不该替它决定何时启动。

### 确认连上了

```bash
# 端点与令牌
type %APPDATA%\HistoryVulcan\service\endpoint.json

# 健康检查（accessToken 取自上面那个文件）
curl -s http://127.0.0.1:<port>/api/health ^
  -H "X-HistoryVulcan-Client: Shell" ^
  -H "Authorization: Bearer <accessToken>"
```

**看 `shells` 字段**：`1` 表示前端已连上，`0` 表示前端在本地模式。

> **不要用命令条数判断前端是否连上。** 网关会从 `web.frontendcatalog` 缓存恢复前端命令，
> 前端没连也能查到它们。宿主迁移时我们就是先按命令条数误判为"已连上"，
> 靠 `/api/health` 才发现 `shells=0`。

## 七、已知会踩的坑

这些是宿主与 Aurora 迁移时真踩过的，按出现频率排：

| 坑 | 症状 | 处置 |
|---|---|---|
| `dotnet test --no-build` 在 build 失败时跑旧 DLL 并报"通过" | 明明改错了却全绿 | **永远先看 build 的 exit code** |
| 批量改名误伤断言字符串 | 测试红，但源码其实是对的 | 失败要逐条判性质，别统一当"适配问题"改断言 |
| 运行中的进程锁住 `bin`，构建报 MSB3027 | 文件占用 | 构建前 `Stop-Process` 掉 `HistoryVulcan` / `HistoryAurora` |
| 带中文的 `.ps1` 缺 BOM | PS 5.1 语法崩坏 | 带非 ASCII 的脚本一律加 BOM |
| `web.frontendcatalog` 按客户端名做键且不回收 | 改名后旧目录成幽灵，命令数虚高 | 手工删该设置键；宿主侧待办 |
